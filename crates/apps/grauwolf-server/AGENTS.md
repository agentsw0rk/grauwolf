## Purpose
The HTTP side in one place: agents as an HTTP service (E11, ADR-0053, ADR-0059, ADR-0060, ADR-0061) and as an A2A server (E09, ADR-0054); started by `grauwolf spec serve`.

## Invariants
- Local only without a token: the CLI binds to `127.0.0.1` by default and requires a token for other addresses; TLS belongs in a reverse proxy.
- A loaded agent serves all requests concurrently; every run has a fresh context.

Delegation in agents (ADR-0111 stage 1): `SpiffeGate::delegating_to(Arc<IdentityClient>)` / `SpiffeInbound::delegating_to` (tests); `SpiffeInbound::start` builds the client from `GRAUWOLF_IDENTITY_URL` with `grauwolf_host::identity::agent_client`. `auth::check`: **entry** – a bearer JWT whose `iss` is the identity service's `person_issuer` (`IdentityClient::is_person_token`; JWT-SVIDs are recognised by their `spiffe://` `sub`) is exchanged for a Txn-Token with the agent's own workload identity (refused 401, the service's policy refusing the agent 403, service or config down 503); **hop** – a `Txn-Token` header is verified (`IdentityClient::verify`: cached JWKS, `aud` = own trust domain, `exp`; invalid 401, keys unreachable 503) only after a SPIFFE caller (peer or JWT-SVID) is mapped in the callers file; from any other caller (shared or user token, anonymous, a person's token) 403; to an agent without identity service 401; **grant run** (stage 3) – a `Grauwolf-Grant` header is accepted only from a mapped SPIFFE caller (else 403; to an agent without identity service 401; together with a `Txn-Token` 400) and exchanged with `IdentityClient::grant(id, caller)`: the service's 403 (wrong trigger or agent, outside its policy) and 401 (unknown, expired, revoked grant, the person's sign-in refused) are passed on, unreachable 503. All three set `Caller::User(<oid>)` and the extension `auth::Delegated` (token + client). `run_agent(agent, input, extras, user, delegated)` is the one place every route runs an agent (`/run`, `/run/stream`, `/api/chat`, the MCP tool, A2A `SendMessage`/`SendStreamingMessage`): it sets `extras.on_behalf_of` and wraps the run in `grauwolf_tools::with_delegation` with a `RunDelegation` (renews near `exp`). Approvals of a delegated run belong to the person (`user` = oid). `ServiceConfig::from_env_with` and `spec serve` refuse `GRAUWOLF_IDENTITY_URL` without `GRAUWOLF_SPIFFE` (`SpiffeServiceConfig::check_identity`). Tests: `tests/delegation.rs`, `an_identity_service_without_spiffe_is_a_start_error` in `tests/service.rs`.
End to end (`a_coordinator_passes_the_person_on_to_the_reviewer_in_one_chain` in `tests/delegation.rs`): alice's Entra token at the coordinator, its A2A tool (`connect_with_auth`, JWT-SVID) carries the Txn-Token to the reviewer, whose run has alice's `oid` as user and the same `txn`. `a_trigger_starts_a_run_on_a_grant_and_the_reviewer_sees_the_person_in_the_same_chain`: the `morning` workload calls the coordinator with alice's grant; `on_behalf_of.grant`, `purp`, `chain_exp` = now + `max_run`; `grant_runs_are_refused_with_the_status_of_the_reason` holds the counter-checks.
