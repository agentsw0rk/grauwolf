# grauwolf-graph

**Layer:** `domain` · **Status:** Edge transformations (ADR-0102, F14.14): an edge may carry a `TransformFn` (`edge_transformed`, `edge_when_transformed`, typed `edge_with`/`erase_transform`) that maps the value after the condition matched and before the target runs; the result is the target's input, so checkpoints store it and a resume does not apply it again; a failure is `EngineError::Transform`. `set_model`/`llm_moderate` take an optional `fallbacks: [{ provider, id }]` (ADR-0088); condition `on_history_tokens_above` (`tokens`, ADR-0087) in the catalog; node catalog: `llm_request`, `store` (`params { key, value }`, `value → value`) and `load` (`params { key, value, type }`, `value → type`) for agent storage (ADR-0044), `set_model` (`params { provider, id, value }`, `value → value`, ADR-0043), `llm_request_best_of` (`params { choices, criteria }`, `string → message`; only the best response enters the history), `llm_request_only_tools` (a tool call is mandatory) and `llm_request_force_tool` (`params { tool }`), both `string → message` (ADR-0042), `llm_continue` (`string → message`; does not append the input; if the history ends with a response, `CONTINUE_PROMPT` follows first, ADR-0041), `llm_verify` (`params { type, prompt }`, `string → Type`; verdict with `correct`/`feedback`, `answer` = the verified answer; F05.13, ADR-0041), `llm_moderate` (`params { type, provider?, id? }` – a model only with both –, `string → Type`; verdict with `harmful`/`categories`/`text`/`message`; F05.17, ADR-0066), `get_field` (`params { type, field }`, `Type → string`, ADR-0041), `llm_reason` (`params { value: string|tool_result|tool_results, prompt }`, `value → string`; think without tools, ADR-0041), `llm_request_streaming` (`string → message`; frames via the frame sink), `execute_tool`, `llm_send_tool_result`, `compress_history` (`params { value, strategy: summarize|keep_last|facts, keep }` – `keep` for keep_last and facts; signature `value → value`; ADR-0037, ADR-0076), `execute_multiple_tools` (`params { sequential? }`, `tool_calls → tool_results`; `sequential: true` runs the calls one after another), `llm_send_multiple_tool_results` (`tool_results → message`), `llm_request_structured` with `params.type` → `string → Named` and optional `params.retries` (≥ 0), ADR-0031. Each kind has `example_params()` for conformance tests and `params_schema()`; `params::check_params` checks the subset object/string/integer(minimum)/number/boolean; unknown parameters are errors. `agent` (`params { agent, input?, output? }`, `input → output`, text by default; the types are those of the sub-agent's spec, declared here because one spec cannot read the others; lists are not allowed; ADR-0101, F14.13) and `decide` (`params { value, kind: choice|yes_no|score, question, options | levels | threshold, yes, no, decider: system_one|llm, model, temperature?, think? }`, `value → value`; each kind accepts only its own parameters; 1–255 unique options/levels, threshold 0–1, the `llm` decider's `model` is written `provider/id`; ADR-0100, F14.12). Condition catalog: `on_decision` (`params { answers }`, a non-empty list of unique answers, passes through; ADR-0100), `on_assistant_message`, `on_tool_call`, `on_multiple_tool_calls` (`message → tool_calls`), `on_history_longer` (`params { messages }`, passes through), `on_field` (`params { field, equals }`, only named types, passes through if the field equals the value; ADR-0041); conditions also have `example_params()`. `DataType::from_name` (`array<T>` is `DataType::Array`, ADR-0101); DataTypes `string`, `message`, `tool_call`, `tool_result`, `tool_calls`, `tool_results`, `Named(<Type>)` (nominal, ADR-0022), `Catalogs`. Untyped engine `Graph<Ctx>` (nodes, conditional edges where the first matching one wins, `NoMatchingEdge`, `max_steps` default 50, `build()` checks edge endpoints); `subgraph(id, graph, scope)` inserts a graph as a node; `Scope<Ctx>` is called on entry and exit – also after errors (ADR-0034); `run` requires `Ctx: Send + Sync`; `run_observed(ctx, input, observer)` reports a serializable `Checkpoint { path, input }` to a `CheckpointObserver` before each node (optionally `node_completed(path, output)` after each node, also for subgraphs); paths run through subgraphs; errors of the observer → `EngineError::Checkpoint`; `resume(ctx, checkpoint, observer)` continues from there – also in subgraphs; scopes are entered again; unknown paths → `EngineError::InvalidCheckpoint`. Typed builder `TypedGraph`/`NodeHandle<I, O>` with compile-time-checked edges; `TypedGraphBuilder::max_steps(n)` sets the step limit (ADR-0078); `subgraph(id, TypedGraph<Ctx, NI, NO>, scope)` returns `NodeHandle<NI, NO>`. `TypedGraph::run_observed`/`resume` as in the engine. `TypedGraph::into_graph()` returns the untyped graph (planner steps). Typed conditions as a filter map (`edge_when`).

Every node kind and condition carries a one-sentence `description()` (an editor's palette, ADR-0126; test `every_node_kind_and_condition_describes_itself_in_one_sentence`).

## Purpose
Graph model, node and condition catalogs, generic `Engine<Ctx>` on `serde_json::Value`, typed builder (`NodeHandle<I, O>`). No node implementations (those live in grauwolf-agents).

## Allowed dependencies
- grauwolf crates: none
- External: serde, serde_json, thiserror, futures-util (no tokio); dev: futures-executor

Other dependencies only after checking against [ADR-0016](../../../docs/adr/0016-layered-architecture.md).

## Invariants
- Exactly one engine for builder, interpreter, and generated code.
- The catalogs are the only source of node kinds and conditions; register new kinds here first.
- Edges in declaration order, the first matching one wins; no matching edge = runtime error.
- Streams never run over edges (ADR-0023).
