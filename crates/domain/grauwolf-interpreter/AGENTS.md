# grauwolf-interpreter

**Layer:** `domain` · **Status:** Code in graphs (ADR-0102, F14.14): nodes `code`, conditions `on_code` and edge `transform`s run built modules from `grauwolf_agents::code` – `load_with_artifacts(spec, artifacts)` takes the artifacts of `spec.code_pieces()` (by piece name) next to the tool artifacts and instantiates them through the tool runtime (`MissingArtifact { tool: <piece name> }`, `MissingToolRuntime`); `build_graph` finds a piece by the JSON pointer of its code (`AgentSpec::graph_pointer`). `Err(msg)` of a code node fails the node with `msg`; a panic, trap or exhausted fuel fails the node, condition or transformation (never `false`). Test `tests/code.rs`. `temperature`/`think` of the spec models go into `LlModel` (ADR-0097; `sampling_echo.json` in the generator's equivalence test). Decisions (ADR-0100): nodes of kind `decide` get their node ID for the events (`implementations::decide(id, params)`); `Interpreter::with_decider(decider)` provides the `system_one` decider to every run (`InterpretedAgent` → `AgentContext::with_decider`); a spec with `decider: system_one` and no decider → `InterpreterError::MissingDecider` at load time; the `llm` decider needs nothing (`examples/specs/ticket_router.json`). Models from the spec, including `fallbacks`, as `LlModel::with_fallbacks` (`llmodel`, main and subgraph model; ADR-0088); `Interpreter::load(spec)` → `InterpretedAgent::run(text)`, or `run_json(value)` for named input/output types (input is checked against the type and normalized, `InterpreterError::Input`); nodes and conditions from `grauwolf_agents::implementations`, a fresh context per run; subgraphs of the spec are attached recursively as engine subgraphs, with `tools` and `model` as a `SubgraphScope` (ADR-0034, ADR-0043); nodes of kind `parallel` run via `grauwolf_agents::parallel::run_parallel` (branches = subgraphs with their scopes, merge from `params`, ADR-0045). Nodes of kind `goap` (ADR-0070) become `grauwolf_planner::planner_node` via `goap::fact_planner(params, steps)`; `steps` contains, for each action subgraph, its graph, attached to a subgraph node with its scope (tools/model). Actions with an `agent` need no graph: the planner runs the sub-agent from `agent_tools` as a step (`run_agent_step`, as an `agent` node). Nodes of kind `plan` become `grauwolf_planner::plan_node` with an `LlmPlanner` over the graph of the step subgraph (its `tools` as the step scope, `critic`, `max_iterations` default `DEFAULT_PLAN_ITERATIONS`, ADR-0039); `with_frame_sink(sink)` passes frames from streaming nodes on. `with_feature(feature)` installs features in every run; `with_interceptor(interceptor)` installs interceptors (ADR-0047); `with_prices(prices)` computes costs in every run; `with_budget(budget)` limits every run (ADR-0072); `agent_completed`/`agent_failed` carry `usage` and `cost` of the run (ADR-0067, ADR-0071); `with_tool_approval(tools)` makes tools require approval: every run (also via `into_tool`) rejects them as long as nobody can approve (`grauwolf_agents::approval::ApprovalGate`, ADR-0061, ADR-0119); `run_with` and the checkpoint runs with `RunExtras.approver` (`ToolApprover`, asynchronous) can approve them (ADR-0077); runs report `agent_starting`, node events (via `AgentObserver`), and `agent_completed`/`agent_failed`. `run_with(input, RunExtras { feature, frame_sink, conversation, tools, approver, memory, attachments, caller })` (`caller`: SPIFFE ID of the calling workload for `agent_starting`, ADR-0109) (`attachments` are appended to the input, also for `run_checkpointed_with`; not for `resume_with` – the input is then already in the history; ADR-0081) gives a single run additional handles (ADR-0053); `tools` replace same-named tools for this run only (`ToolRegistry::extended`, ADR-0059); `run_json` and `run_conversation` use it. With `long_term_memory.auto_recall` and `RunExtras.memory`, the facts most relevant to the input are appended as a system message before the run; with `auto_remember`, after a successful run (before `agent_completed`), `extract_facts` pulls durable facts that are not yet known (known ones are recalled beforehand via `FactMemory::recall` for the input) from input and output, and stores them via `FactMemory::remember` (errors → `memory_failed`, the run continues; ADR-0069). With `long_term_memory.remember_compressed`, the lifecycle receives `RunExtras.memory` with `AgentRun::remember_compressed` (`Interpreter::with_memory`, all three run kinds; the lifecycle gives it to the context, ADR-0079, ADR-0116). `run_conversation(input, store, conversation_id)` continues conversations (loads the history after the system prompt; on success, saves it without the system prompt; ADR-0037). `run_checkpointed(input, store, run_id)` saves the `ExecutionState` before each node; `resume(store, run_id)` continues from the last checkpoint (`NoCheckpoint`, `Checkpoint` errors). `run_checkpointed_with(.., extras)`/`resume_with(store, run_id, extras)` take `RunExtras` like `run_with` (tools, approver, memory, feature, frame sink; conversation → `CheckpointConversation`); with `auto_remember`, the input is stored under `grauwolf.run_input` so that even a resumed run stores facts; `resume_with` rebuilds the self-built tools from `ContextSnapshot.self_tools` via the factory and puts them on the shelf before continuing (errors → `SelfToolRebuild`; `CreateTool` stores them with `put_made`) (ADR-0077); shared helper `with_handles`. Loads only validated specs (`InterpreterError::Invalid`). `limits` (ADR-0078): `max_steps` for every built graph (`GraphBuilder::max_steps`), `max_tokens`/`max_cost`/`max_tool_calls`/`max_prompt_tokens` (ADR-0087) as a `Budget` (`budget_for`: fields from `with_budget` take precedence); `max_cost` without prices → `CostLimitWithoutPrices`. Spec tools: `with_tool_runtime(..)` + `load_with_artifacts(spec, artifacts)` (artifacts from grauwolf-toolbuild, executed e.g. in grauwolf-sandbox); missing artifacts or runtime are errors. `into_tool_with(name, description, extras: ExtrasProvider)` gives each call handles (`run_with`, ADR-0089); `Arc<InterpretedAgent>::into_tool(name, description)` offers the agent as a `DynTool` (a fresh context per call; argument `{ request }` for text input, otherwise the schema of the input type; structured output as JSON text; errors → `ToolError::Execution`; ADR-0040). Self-created tools (ADR-0075): `with_tool_factory(factory)`; a spec with `self_tools` but no factory → `MissingToolFactory` at load time. Every run gets a fresh `ToolShelf` on its registry and the tool `create_tool` (`self_tools.rs`: checks snake_case names, existing tools, `max_tools`, `max_code_bytes`; also accepts a whole `fn tool(…)` instead of a body and then appends `tool(args)`; builds via the factory; puts it on the shelf; every error becomes a tool result); with `confirm`, it requires approval as with `with_tool_approval`. Which tools those are comes from `AgentSpec::approval_tools()` (ADR-0119), `budget_for` is `grauwolf_agents::run_handles::merged_budget`. Likewise `run_command` requires approval when `builtin_tools.command` is in shell mode with `approve_each_call` (`CommandSpec::needs_approval`, ADR-0099): rejected without an approver, asked per call with one. `RunExtras.tools` and `create_tool` are created in `equip`; the context gets `with_self_tools(tool, enabled)`, and subgraphs with `self_tools` get a build permission in their `SubgraphScope` (also applies to `plan`, `parallel`, `goap`). Tools of resolved tool packages (ADR-0107, `ResolvedTool` from grauwolf-tools) via `with_package_tools(..)`: instantiated through the tool runtime like spec tools (`MissingToolRuntime` without one) and all offered. External tools (`AgentSpec::external_tools()`) via `with_tools(..)`; every tool declared in `mcp_servers`, the search tool from `knowledge`, every sub-agent from `agent_tools`, and every built-in tool from `builtin_tools` must be provided (`MissingExternalTool`).

Skills (ADR-0103): the registry's `prompt_addition()` (the skill list of the external tool `load_skill`) is appended to the system prompt at load time (`Prompt::extend_system`); the skill tools themselves come through `with_tools` like every external tool and are declared by `AgentSpec::external_tools()`. Test `tests/skills.rs`.

Flows (ADR-0101): an agent as a tool (`AgentTool`) also implements `DynTool::call_step`: the `agent` node runs it with the value as input (typed values stay JSON, no text round trip) and the calling run (`InterpretedAgent::run_as_step(input, extras, parent: Option<Arc<ParentRun>>)`): the sub-agent's context adopts the parent's counters, so usage, cost, tool calls and budget are shared, and it uses the parent's approver (the run handle of `equip` is the `ToolApprover`) unless the extras bring their own. History, tools and events stay the sub-agent's own.

Node `for_each` (ADR-0101): `for_each_node` builds `grauwolf_agents::for_each::ForEach` from `ForEachParams` (agent body or subgraph body with its scope; `output: string` returns the list as JSON text) and runs `run_for_each`; progress under `grauwolf.for_each.<id>` makes checkpoint resumes do only the missing elements.

`RunExtras.trace_parent` (ADR-0123): the caller's trace context, handed to `AgentRun::with_trace_parent` in `run_with`, `run_as_step` and the other runs, like `caller`.

Package tools are loaded with `ToolRuntime::instantiate_limited` and their `ResolvedTool.limits` (ADR-0124).


## Purpose
Runs a validated AgentSpec as an agent without compiling it.

## Invariants
- Accepts only validated specs.
- Behavior must match the generated code (equivalence tests on examples/specs/).
- Tool code is not compiled; only the finished artifact is loaded via `ToolRuntime` (ADR-0024).

## Knowledge as context (ADR-0113)
With `knowledge.inject` the loaded agent takes the `KnowledgeContext` of the provided search tool of `knowledge` (`grauwolf_tools::knowledge_context_of` by the tool name; missing → `MissingExternalTool`); before every run from a new input (after the automatic recall, in the run lifecycle) `grauwolf_agents::knowledge::inject_knowledge` appends the best sections as a system message and emits `knowledge_injected { sources, count }` (`knowledge_failed { error }` on failure, the run continues). With `tool_enabled: false` the tool is provided but not offered (`external_tools()` leaves it out). Test `tests/knowledge_context.rs`.

Run lifecycle (ADR-0116): `run_as_step` (also `run_with`/`run_conversation`), `run_checkpointed_with` and `resume_with` only prepare the context (`equip`, handles, compressed memory) and hand the run to `grauwolf_agents::run_lifecycle::AgentRun` (`lifecycle()` adds memory and knowledge; options for attachments, conversation, checkpoints, `resumed()`); the order of events, recall, injection, remember and conversation saving lives there, so a conversation is saved before `agent_completed` and a failed save is `agent_failed`. `RunError` maps to `InterpreterError`; the graph is an `Arc<Graph>` so the graph run can be passed in as a function.

`RunExtras.on_behalf_of` (ADR-0111): the person of a verified Txn-Token, handed to `AgentRun::with_on_behalf_of` in every run kind like `caller`.
