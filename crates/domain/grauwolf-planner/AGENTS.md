# grauwolf-planner

**Layer:** `domain` · **Status:** Trait `Planner` (`initial_state`, `build_plan(ctx, state, plan)`, `execute_step`, `is_completed`, `output`) and `run_planner(planner, ctx, input, max_iterations)` (plan → step → check; the plan may be rebuilt before each step; `PlannerError::MaxIterations`). `LlmPlanner::new(step_graph)`: the plan (`Plan { goal, steps: [PlanStep { description, completed }] }`) as a structured response in its own history (the planner's system prompt + task + previous results; the agent's history stays untouched); each step runs as the instruction "Goal: … Carry out step i of n: … and answer with the result." (a built-in model instruction) through the graph (text → text, e.g. with a tool cycle) in the agent's history; state `PlanState { task, results }`, output = result of the last step. `with_critic()`: before each further step, a critic evaluates the plan and results in its own history (`{ should_continue, reason }`); on rejection, the plan is rebuilt with the discarded plan and the reason (F10.3). `run_planner` reports `AgentEvent::PlanBuilt { iteration, plan }` and `PlanStepExecuted { iteration, plan }` (plan as JSON, hence `Plan: Serialize`; F10.7). `with_step_scope(scope)` enters the scope around each step (tool subset of the step subgraph). `plan_node(Arc<LlmPlanner>, max_iterations, node_id)` is the node function (saves progress after each step under `grauwolf.plan.<node_id>` and resumes from there, `run_planner_resumable`, ADR-0052) of kind `plan` (text → text) for the interpreter and generated code. `goap::GoapPlanner::builder(initial, output).action(Action::new(name, precondition, belief, execute).cost(..)).goal(Goal::new(name, condition).heuristic(..)).build()` (F10.4/F10.5): A* per goal over the expected effects (`belief`), cheapest path across all goals, plan = action names; before each step it re-plans from the actual state; search limited to 10,000 states and 50 actions; no path → `PlannerError::NoPlan`. `GoapPlanner::plan(state)` is that plan without a context, the search alone (what `build_plan` uses); `goap::expected_plan(params)` builds the planner of a `goap` node without executors and returns the plan for its start state (empty task) or the reason there is none – the studio shows it as the expected plan (ADR-0126 decision 15). **Goal:** data-driven GOAP in the DSL (ADR-0070): `goap::fact_planner(params, steps)` builds a `GoapPlanner<String, String, FactState>` from the parameters of a `goap` node (`state`, `actions` with `pre`/`effects`/`cost`/`description`/`subgraph`, `goals` with `facts`); each action runs its executor – the graph of its `subgraph` or the sub-agent `agent` as a step (`AgentContext::run_agent_step`, ADR-0101) – with the `input` template (`{{fact}}`, `{{task}}`) or `"<task>\n\nAction: <name>"` (a built-in model instruction); the answer goes to `output_fact`, `success_contains` decides success, then `on_success` (default `effects`) or `on_failure` apply (without `on_failure` a failure fails the node; an executor failure while the run budget is exhausted – `AgentContext::budget_exhausted()` – always fails the node, `on_failure` or not); planner `input_fact` receives the node input, `output_fact` delivers the result; facts are `FactValue::{Bool, Int, Number, Text}` (the type follows the initial value in `state`; texts with a list under `values` are enumerations, without free texts); conditions (`pre`, goal `facts`) are a plain value or one operator `eq|ne|gt|lt|ge|le`, effects a value or `{ "add": n }` (module `facts`, addendum to ADR-0070); fields of an object output overwrite same-named facts of the same kind, and enumeration texts only with an allowed value; goals have a `priority` (`Goal::priority`; the plan with the smallest `cost / (priority + 1)` over all goals wins, ties by declaration order); the search is bounded by `max_search_nodes` (default 10,000) and `max_plan_depth` (default 50; builder and parameters); result = output of the last action (or `output_fact`). `planner_node(planner, max_iterations, node_id)` turns any planner with text input/output and serializable state into a node with progress under `grauwolf.plan.<id>`; `plan_node` is the short form for the LLM planner.

## Purpose
Planner agents (E10): create plans, execute them step by step, re-plan when needed.

## Features / ADRs
E10 (F10.1–F10.7), ADR-0039, ADR-0052, ADR-0070

## Allowed dependencies
- grauwolf crates: grauwolf-agents, grauwolf-graph, grauwolf-llm, grauwolf-prompt; dev: grauwolf-test, grauwolf-tools
- External: futures-util, serde, serde_json, thiserror; dev: futures-executor

Other dependencies only after checking against [ADR-0016](../../../docs/adr/0016-layered-architecture.md).

## Invariants
- No LLM or tool logic of its own alongside `AgentContext`: planners use its requests, and steps run via the engine.
- Every run is bounded by `max_iterations`.
