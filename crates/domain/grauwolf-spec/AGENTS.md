Tool packages (ADR-0107, F03.18): `tool_packages: [ToolPackageSpec { oci | git (+ path?, one of rev/tag/branch), tools?, as }]`; `GitSource::from_entry` parses a git entry (`https://`, `http://` only for `localhost`/`127.0.0.1`, no user info, `rev` 7–40 lowercase hex, `path` relative without `..`; `GitSourceProblem { field, reason }`) and `lock_key()` gives the lockfile key `git+<url>[//<path>]@<rev | tag:<tag> | branch:<branch>`; git fields next to `oci` are `InvalidGitSource`; `OciReference::parse` (`registry/repository[:tag][@sha256:…]`, explicit registry host, tag defaults to `latest`); validation reports `ToolPackageSource` (not exactly one of `oci`/`git`), `InvalidGitSource { reason }` at `/tool_packages/<i>/<field>` (never repeats the URL), `InvalidOciReference { reason }` at `/tool_packages/<i>/oci`, `InvalidId`, `UnknownTool` (rename of an unselected tool) and `DuplicateToolName` (after renaming, against inline and external tools). Selected tools (`tools`) count as known tools (the tool namespace, e.g. for subgraph tool lists); tools of a package without `tools`, the ABI version and unknown package tools are only checked when the package is resolved (validation never needs the network).

Warnings: `AgentSpec::warnings()`/`warnings_with(&Catalogs)` return `Vec<SpecWarning { pointer, message }>` (`Display`: `<pointer>: <message>`); they never fail the validation. First warning: a node whose output type is `message` (so its answer can carry tool calls, derived from the node catalog) has an `on_tool_call` edge but no `on_multiple_tool_calls` edge (at `…/nodes/<i>`, subgraphs included).

Flows (ADR-0101, F14.13): `AGENT_KIND` = `agent` (catalog node); the check names its `agent` in `agent_tools` (`UnknownAgent`, pointer `…/params/agent`); node types may be `array<T>`, whose element type must be declared (`UnknownType`).

`FOR_EACH_KIND` = `for_each` (not in the catalog, like `parallel`; ADR-0101): `ForEachParams::parse` (in `grauwolf-spec-model`, shared with interpreter and generator) reads `{ input: array<T> | string, output: array<U> | string, body: { agent } | { subgraph }, max_parallel 1..=16 (default 1), on_error fail|skip }`; the checks name unknown agents (`…/params/body/agent`) and subgraphs, `max_parallel`, list types, undeclared element types and a subgraph body whose `T → U` does not fit the element types of `array<T>`/`array<U>` (text input or output means no check); a body subgraph counts for the cycle check; `AgentSpecExt::check_sub_agent_types(&signatures)` compares the declared types of `agent` nodes and `for_each` agent bodies (element types of the lists) with the (input, output) of the sub-agents' specs (`SubAgentTypeMismatch`); the callers that can read files hand the signatures in; subgraph signatures may use `array<T>`.

Palette (ADR-0126): `STRUCTURAL_NODE_KINDS` (`subgraph`, `plan`, `goap`, `parallel`, `for_each`, `code`) and `STRUCTURAL_CONDITION_KINDS` (`on_code`) in `grauwolf-spec-model` – `StructuralKind { kind, description }`, the kinds outside the catalogs; `tests/structural_kinds.rs` keeps them known to the validation.

## Where things live (ADR-0108 stage 6)
The data model moved to `grauwolf-spec-model` (types, `AgentSpec::parse` without strategy expansion, JSON schema, `external_tools`, `provider_uses`, `providers`, `uses_system_one`, `to_json`, `to_mermaid`); this crate re-exports it with `pub use grauwolf_spec_model::*`, so every `grauwolf_spec::…` path stays valid. What stays here: loading with strategy expansion, validation and the warnings. They cannot be inherent methods of a type from another crate, so they are the extension trait `AgentSpecExt` (`from_json`, `validate`, `validate_with`, `warnings`, `warnings_with`) – import it with `use grauwolf_spec::AgentSpecExt;` (generated code does that itself). The strategy templates moved to `grauwolf-strategies`; `from_json` = `AgentSpec::parse` + `grauwolf_strategies::expand` + merging the expansion (type collisions, strategy next to `graph`). The rules of `src/validate/` are methods of the private wrapper `Rules<'_>` (dereferences to `AgentSpec`).

## Where the validation rules live
`src/validate/` (ADR-0108): `mod.rs` holds the public entry points (`validate`, `validate_with`, `warnings`, `warnings_with`), `ValidationError`/`ValidationErrorKind`, `SpecWarning`, `GraphScope` and the shared identifier helpers. `validate_with` calls the rules in a fixed order, and the order of the collected errors is observable (tests compare full lists), so keep it when adding a rule. One module per concern: `schema` (name, type names and schemas, input/output), `tools` (tool namespace) and `tool_packages`, `models` (fallbacks, sampling), `builtin_tools`, `sections` (MCP, agent tools, knowledge, long-term memory, self tools, limits), `subgraphs` (definitions, `plan`, `parallel`, cycles) and `goap`, `graph` (scopes, node IDs and kinds, condition kinds, edge endpoints), `edges` (edge type checking), `reachability`, `decisions`, `warnings`. Rules are `pub(super)` methods of `AgentSpec` or functions; helpers with unit tests sit next to them.

Skills (ADR-0103): `validate/skills.rs` checks every `skills` entry (exactly one of `dir`/`git` → `SkillSource`, directory form and git source → `InvalidGitSource` with the field pointer, names → `InvalidId`) and reserves `load_skill`/`read_skill_file` (`DuplicateToolName` for an own tool of that name; the names are in `external_tools()` otherwise). What is inside the folders is not checked here (no IO): `grauwolf_builtin_tools::SkillLibrary` does that when they are loaded, `spec validate` for local ones.

## Invariants
- Every tool-name collision comes from `Rules::check_tool_collisions` over `AgentSpec::tool_namespace()` (ADR-0117): `DuplicateToolName { name, other_origin, other_pointer }` at the later declaration (order: own, MCP, knowledge, memory, built-in, skills, sub-agents, packages, self-build, code pieces); each check calls it for its own origin at its place in `validate_with`'s fixed order. Built-in groups, sections and `root` come from `BUILTIN_GROUPS`.
- Validation collects **all** errors, each with a JSON pointer (RFC 6901). Format errors while parsing (unknown field, missing required field, wrong type) come through `serde_path_to_error` as `SpecError::Format { pointer, message }` with an English message; only invalid JSON stays `SpecError::Json` with line/column (ADR-0080).
- Type schemas: an object with fields of `string`/`integer`/`number`/`boolean`/`array` (with `items`); field names in lowercase – otherwise `UnsupportedSchema` at the pointer (the same subset as the generator, ADR-0080). GOAP actions/goals: unknown keys → `InvalidParams` (`check_keys`).
- Error texts are understandable to humans and LLMs.
- `deny_unknown_fields` on all structs; no `flatten`/`untagged` (ADR-0025).
- `kind` is a string (no own enum) and is checked against the node catalog from grauwolf-graph (`validate` = built-in catalogs, `validate_with(&Catalogs)` = own); conditions (`when.kind`) likewise against the condition catalog. Invalid `params` are reported by the catalog's signature function (`InvalidParams` at `/graph/nodes/<i>/params`); if a signature names an undeclared type, `UnknownType` follows there. The `params` of nodes and conditions are first checked against the `params_schema()` of their catalog kind (`InvalidParams` with reasons such as `/extra: unknown parameter`, at `/…/params` or `/…/when/params`).
- Tool names are unique snake_case identifiers (own namespace).
- Type names in `types` are PascalCase identifiers (`[A-Z][A-Za-z0-9]*`; they become Rust structs).
- `input`/`output` refer to `string` or a name from `types`; otherwise `UnknownType` at `/input` or `/output`.
- The spec name is a snake_case identifier (it becomes the crate name of generated agents).
- Edges are checked in `from` and `to` against existing nodes. `start`/`finish` are reserved and forbidden as node IDs. Node IDs are unique snake_case identifiers (`[a-z][a-z0-9_]*`).
- Subgraphs (ADR-0034): names are snake_case identifiers; `input`/`output` are known types; `tools` must appear in `tools` (`UnknownTool`); every subgraph graph is checked like the main graph (paths `/subgraphs/<name>/graph/...`; `start`/`finish` with its signature). Nodes of kind `subgraph` (not in the catalog) need `params.subgraph` (`UnknownSubgraph`) and take its signature; self-inclusion (also indirect) is `SubgraphCycle`. Nodes of kind `plan` (ADR-0039, also not in the catalog; `PLAN_KIND`, `plan_params_schema()`) need `params.subgraph` with signature string → string, optionally `critic` (bool) and `max_iterations` (≥ 1, default `DEFAULT_PLAN_ITERATIONS`); signature string → string; errors as `InvalidParams { kind: "plan" }` or `UnknownSubgraph`; they count as inclusion in the cycle check. Nodes of kind `parallel` (ADR-0045, `PARALLEL_KIND`, not in the catalog) need `params.subgraphs` (≥ 2 known subgraphs with the same signature, which becomes the node's signature) and `merge` (`concat` only with output string; `index` with a valid `index`; `llm_select` with optional `criteria`); other parameters are errors; all branches count in the cycle check. Nodes of kind `goap` (ADR-0070, `GOAP_KIND`, not in the catalog; signature string → string) need `state` (facts `{ name: bool | integer | number | text }`; the type follows the initial value, a text with a list under `values` is an enumeration, otherwise free text – addendum ADR-0070), optionally `values` (`{ fact: [text, …] }`, only for text facts), `actions` (≥ 1; `name` unique; exactly one of `subgraph` (known, input string) or `agent` (`UnknownAgent` unless in `agent_tools`); `pre` conditions as a value or one operator `eq|ne|gt|lt|ge|le` (ordering only for integer/number), `effects`/`on_success`/`on_failure` as a value or `{ "add": n }` (numbers only), all only with facts from `state` and values of their type; `input` template with placeholders `task` or a fact; `output_fact` a free-text fact; `success_contains` text; `cost` ≥ 0), `goals` (≥ 1; `name`, `facts` likewise, `priority` integer ≥ 0), optionally `input_fact`/`output_fact` (free-text facts), `max_iterations`, `max_search_nodes`, `max_plan_depth` (each ≥ 1); other parameters are errors (`InvalidParams { kind: "goap" }`); all action subgraphs count in the cycle check and appear as attached in `to_mermaid()`.
- Reachability (F13.5): `finish` must be reachable from `start` via edges (`FinishUnreachable` on the graph path); every node likewise (`UnreachableNode` at `/…/nodes/<i>`); and from every reachable node there must be a path to `finish` (`DeadEnd`, only checked if `finish` is reachable at all). Conditions count as possible. Applies to the main graph and to subgraphs.
- MCP servers (ADR-0036): names are snake_case identifiers; their declared tools share the namespace with `tools` (`DuplicateToolName`) and may appear in subgraph `tools`.
- `provider` is a string (custom providers are possible). `spec_version` is checked before typed deserialization (only version 1).

- Edges are type-checked: output of the source → (condition) → input of the target. If a condition does not fit the value, this is reported at `/when`. `start` yields the type from `input`; `finish` expects the type from `output`; named types are compared nominally (`DataType::Named`, ADR-0022).
