# grauwolf-agents

**Layer:** `domain` · **Status:** `code` (ADR-0102, F14.14): `CodeModule` (a built code module run through `DynTool`, JSON in and out) with `code_node`/`code_node_typed`, `code_condition` (passes the value on when the code answers `true`) and `code_transform` for the interpreter and generated code; pure functions of the value, `Err(msg)` fails with `msg`. The agent storage is behind a `Mutex`, so `execute_tool` can keep the state of tools with a `state_key` in it (`call_tool`: the whole call under the lock, state kept only on success; part of `snapshot()`, so it survives a resume; ADR-0098). `model_from_params` also reads `temperature` and `think` (ADR-0097). `LlmCallCompleted.model` carries `Completion.model` (ADR-0094); Fallback models (ADR-0088): `set_model`/`llm_moderate` read `fallbacks` from the parameters (`model_from_params`); node `nodes::switch_model::<T>(model)`; `with_fallbacks(model, request)` asks the model and – if the request fails (except `BudgetExceeded`) – tries `model.fallbacks` one after another, reports each switch as `llm_fallback { from, to, error }`, and books usage/cost to the model that answered (`llm_call_finished_by`); the active model stays; applies to `request_llm`, structured, JSON, multiple responses, summarization, facts, and moderation (whose own model comes with its fallbacks); streaming switches only as long as no frame has been passed on. `memory::recall_facts(ctx, memory, input)` (most relevant facts as a system message, `MemoryRecalled`/`MemoryFailed`), `memory::remember_facts(ctx, memory, input, output)` (recall known facts, `extract_facts`, store new ones), and `memory::text_of(value)` – shared by the interpreter and generated code (ADR-0069, ADR-0084). Minimal `AgentContext` (executor, model, history, tools, optional frame sink `with_frame_sink`; tool subsets as a stack `enter_tool_scope`/`leave_tool_scope`: `tool_descriptors()` offers only allowed tools, `execute_tool` rejects others with an error text; `scopes::ToolSubset` is the matching `Scope` for subgraphs, ADR-0034; self-built tools (ADR-0075): `with_self_tools(tool, enabled)` and `enter_building_scope(allowed)` (same stack, left with `leave_tool_scope`) – `tool` and the tools of the `ToolShelf` follow the innermost build permission (otherwise `enabled`); a tool list further inside hides them; `SubgraphScope::with_self_tools(allowed)`). Nodes `llm_request`, `llm_request_streaming` (frames to the sink; aggregated response over the edge; ADR-0023/0033), `execute_tool` (tool errors as result text), `llm_send_tool_result`, `execute_multiple_tools` (all calls of one response concurrently via `join_all` in the same task; results in call order; with `sequential: true` the node `execute_tools_in_order` runs them one after another in call order, each call with its own events, interceptors, approval and tool call limit), `llm_send_multiple_tool_results`, `llm_request_structured::<T: Structured>` (response as the type; code block allowed; `AgentContext::request_llm_structured(output, retries)`; `request_llm_json(output)` requests structured output and returns the response unchecked, e.g. for the DSL schema), and `llm_request_structured_with_retries::<T, N>` (an error is reported to the LLM, up to N new attempts; F01.11). Conditions `on_assistant_message` (response without tool calls → text), `on_tool_call` (response with exactly one tool call), `on_multiple_tool_calls` (at least one call → all calls). Value implementations for the interpreter in `implementations` (`node(kind, params, types)`; `llm_request_structured` takes the schema from the spec types) (conformance test against the catalog). History compression (F05.14, ADR-0037): `AgentContext::compress_history(..)`: nodes `compress_history_summarize::<T>`/`compress_history_keep_last::<T, N>`/`compress_history_facts::<T, N>` and conditions `on_history_longer::<T, N>` and `on_history_tokens_above::<T, TOKENS>` (tokens via `AgentContext::prompt_tokens()`; tokenizer from `with_tokenizer`, default `EstimatingTokenizer`; forks inherit it; ADR-0087) (also as value implementations). `Summarize` replaces the history with an LLM summary (as a user message); `KeepLast(n)` keeps the system prompt and the last n messages, never starts with an orphaned tool result; an open tool call stays. `with_fact_memory(memory)` (ADR-0079): the `Facts` compression additionally asks for `durable` and stores these durable facts via `FactMemory::remember` (`memory_remembered`/`memory_failed`; the compression continues). `Facts(n)` (F05.15, ADR-0076) keeps the last n messages like `KeepLast` and replaces the older ones with a user message `FACTS_HEADER` + `- fact` per line; the facts come from a structured request `{ facts }` to the active model (history as text; an earlier fact list is absorbed in it; shared helper `request_facts` with `extract_facts`; usage counts, budget is checked); nothing older → no request. Chat memory (F07.1, F07.2, ADR-0037): port `memory::ChatHistoryStore` (load/save per conversation ID; history without the system prompt), `MemoryChatHistoryStore`; port `memory::FactMemory { recall(query), remember(facts) }` (`MemoryError`) for automatic memory, events `memory_recalled/remembered/failed`; `AgentContext::extract_facts(input, output, known)` (its own structured request `{ facts }` with the active model; `known` as "Already known" – only new facts, not even reworded; history untouched; usage counts toward the total; ADR-0069); `conversation_key(user, id)` builds the storage key (`id` only `[A-Za-z0-9_-]`; with a user `users/<hex>/<id>`; user 1–128 bytes, checked by `check_user_id(user)`, which services also use at their entry; ADR-0060). Events (F06.1, F06.3, ADR-0007): `events::AgentEvent` (serializable, `event` tag: agent_*, node_*, llm_call_starting/completed/failed (`llm_call_completed` with `usage` when the provider reports it – normal and structured requests via `execute_with_usage`/`execute_structured_with_usage`, streaming via the last `StreamFrame::Usage`, and the reported model via `StreamFrame::Model` of the answering candidate; ADR-0067), tool_call_starting/completed (after a successful `load_skill` call `skill_loaded { name }` follows, ADR-0103; `execute` in `tool_execution.rs` emits it because the tool itself cannot), moderation_starting/completed/failed – without the checked text, ADR-0066), `Feature::on_event`, `AgentContext::install(feature)`/`emit(event)`; LLM and tool calls of the context report themselves. `observer::AgentObserver` reports node events (`node_starting`/`node_completed`) and optionally stores checkpoints (`with_checkpoints(store, run_id)`). Checkpoints (ADR-0020, ADR-0034): `AgentContext::snapshot()`/`restore(executor, snapshot)` (history + model + storage; `ContextSnapshot.self_tools` = definitions of self-built tools from `ToolRegistry::self_made()`, absent in older checkpoints, ADR-0077; `usage`/`cost`/`tool_calls` = consumption so far; `restore` continues it, ADR-0077 addendum); `checkpoints::ExecutionState { version, checkpoint, context }`; port `CheckpointStore` (save/load per run ID); observer `Checkpointing` stores before each node. `MemoryCheckpointStore` for tests and short-lived runs. `structured::normalize(schema, value)` checks values against the schema subset of the spec types and normalizes them like a serde roundtrip through the generated struct (ADR-0031). **Goal:** guard sessions, ExecutionState, pipeline (ADR-0020, ADR-0026, ADR-0027); planner events `PlanBuilt`/`PlanStepExecuted` (reported by grauwolf-planner). Agent storage `store(key, &value)`/`load::<T>(key)` (part of `ContextSnapshot.storage`, ADR-0044); `fork()`/`absorb(branch)` (ADR-0045); `parallel::run_parallel(ctx, branches, input, merge)` (branches run concurrently on forks with an optional scope; `Merge::Concat` → `## <branch>` sections, history unchanged; `Merge::Index(i)` takes the result and context; `Merge::LlmSelect { criteria }` lets the same evaluation as `llm_request_best_of` pick the branch) and `parallel::parallel::<I, O>(branches, merge, node_id)` for typed code; `run_parallel_resumable(.., key)` saves each finished branch (result + context) under `progress_key(node_id)` = `grauwolf.parallel.<id>` and, on resume, runs only missing branches; `apply(snapshot)` (ADR-0052); `model()`, `set_model(model)` (history stays); `enter_model_scope`/`leave_model_scope`; `scopes::SubgraphScope::new().with_tools(..).with_model(..)` (sets on entry, restores on exit; the snapshot stores the model outside all subgraphs; ADR-0043); `request_llm_choices(n)` (n responses, nothing appended); `request_llm_with(tool_choice)` sets the tool choice for one request only (ADR-0042). If the model cannot force it (`PromptExecutor::forces_tool_choice`), for `Required`/`Tool(name)` it permanently appends a system instruction and asks with `Auto`; if the call is missing, the response is discarded (not appended) and asked again exactly once (ADR-0063). Interceptors (ADR-0047): `events::Interceptor` with `before_llm_call(&mut Prompt, &mut Vec<ToolDescriptor>)` (only for the request) and `after_llm_call(&mut Message)` (before appending); `before_tool_call(&mut ToolCall) -> ToolDecision::{Proceed, Deny(text)}` (denied → `text` as the result) and `after_tool_call(&mut ToolResult)`; asynchronous `approve_tool_call(&ToolCall) -> BoxFuture<ToolDecision>` after all `before_tool_call` (approval; may wait; ADR-0061); `AgentContext::intercept(..)`. Applies to all request kinds, including streaming (frames unchanged, response afterwards) and summarization; before a moderation, `before_llm_call` sees the text as the prompt `MODERATION_PROMPT_ID` with a user message, and the text is checked afterwards (ADR-0047 addendum); forks inherit them. `AgentContext::usage()` sums the token usage of all requests including forks (shared counter; new after `restore`; ADR-0067); `agent_completed`/`agent_failed` carry the sum as `usage`, set by the interpreter. Budget (ADR-0072): `with_budget(Budget { max_tokens?, max_cost?, max_tool_calls?, max_prompt_tokens? })` checks the sum including forks before every LLM request, and with `max_prompt_tokens` the estimated tokens of the history (`prompt_tokens()`, ADR-0087), and otherwise returns `LlmError::BudgetExceeded`; `budget_exhausted()` returns the reason once the budget no longer allows a request (`None` before), for callers that catch step failures (GOAP `on_failure`); `max_tool_calls` (ADR-0078) counts executed tool calls including forks under a lock (`claim_tool_call`); beyond it no tool runs, and the result is `tool_limit_message` (checked before the interceptors, so also without an approval prompt). Costs (ADR-0071): `with_prices(Arc<Prices>)`, `llm_call_completed.cost` per call (active model), `cost()` as the sum including forks (shared counter); fact requests count too; likewise moderation (cost at the moderation model's price, `add_usage_for`; `moderation_completed` with `usage`/`cost`) and `request_llm_choices` (usage/cost on the event of the first response; ADR-0067 addendum). Moderation (ADR-0066): `AgentContext::moderate(text, model?)` (active model by default; history untouched); node `llm_moderate::<T>(model?)` (`string → T` with `{ harmful, categories, text, message }`, where `message` = rejection with categories, empty if harmless). Progress in long nodes (ADR-0052): `save_progress()` writes the context as the new state of the running checkpoint via the hook from `AgentObserver::progress_saver()` (`set_progress_saver`, `checkpoints::ProgressSaver`; forks have no hook); `remove(key)` removes storage entries. `attach_to_input(attachments)` attaches attachments to the next user message that has none of its own (the run's input; `append` takes them; forks inherit open ones; ADR-0081). `replace_prompt(prompt)` swaps the history (side requests on their own history, e.g. planners). Decisions (ADR-0100, F14.12): node `decide` (`nodes::decide::<T>(node_id, params_json)`; `implementations::decide(node_id, params)`; the value passes unchanged; `T` is the state, text as text, other values as JSON), condition `on_decision` (`conditions::on_decision(ctx, &answers, value)`) – the verdict lives in the agent storage under `decision::DECISION_KEY` = `grauwolf.decision` as `DecisionRecord { node, answer, probability?, confidence?, probabilities, model? }`, so `on_decision` reads the latest one; `decision::decide` is the shared core: events `decision_starting { node }`, `decision_completed { node, answer, probability?, confidence?, model? }`, `decision_failed { node, error }` (never the state), then the answer is checked against the allowed ones; `DecisionNode::from_params` reads the node parameters (`DeciderKind::{Llm, SystemOne}`); `AgentContext::with_decider(Arc<dyn Decider>)` provides the external (`system_one`) decider – without it a node naming it fails; the model decider needs nothing. Also: `decision::{Decision, DecisionKind, ChoiceOption, Verdict}`, port `Decider::decide(&Decision, &state)` (`DecideError::{Transient, Failed}`) and the answer rules every decider shares: `DecisionKind::answers()`, `answer_for_probability` (yes at or above the threshold), `answer_for_score` (round the mean index, clamp it to the scale), `Decision::accepts(&Verdict)`; `RetryingDecider::new(inner, RetryPolicy, Clock)` asks again after a `DecideError::Transient` as the policy allows (waits via the `Clock`; permanent errors pass at once). The model as a decider (`llm`): `AgentContext::decide_with_model(&decision, &state)` asks `decision.model` (written `provider/id`) or the active model (with `decision.temperature`/`think` for this request only) without tools for a structured answer – `{ answer }` with an enum of the options/levels, or `{ probability }` for `yes_no` (the threshold decides) – on its own prompt (history untouched; the state is text as is, other values as JSON, marked as data); LLM call events, usage, costs, budget and fallbacks as for every request; an answer outside the allowed ones is an error.

Flows (ADR-0101, F14.13): `flows::ParentRun` (the shared counters and the runtime handle of the calling run), `AgentContext::run_agent_step(name, input)` (looks the sub-agent up in the tool registry regardless of tool scopes and runs `DynTool::call_step` with the run as `StepHandles`), `AgentContext::with_run_handle(handle)` (opaque runtime handle, e.g. the approver; forks inherit it) and `adopt_run(&ParentRun)` (a sub-agent's own context counts on the parent's usage, cost and tool-call counters and obeys its limits; history, tools, model and storage stay its own).

Node `agent` (`nodes::agent_step::<I, O>(agent)`; `implementations::node("agent", ..)`): `run_agent_step` with the passing value.

`for_each::run_for_each(ctx, &ForEach, node_id, input)` (ADR-0101): the elements of a list (a JSON array, or text holding one, also inside a code fence; anything else is an error) run `Body::Agent(name)` (as `run_agent_step`) or `Body::Graph { graph, scope }` each on its own `fork()` (copy of the history at the start, shared counters), `with_text_output()` returns the list as JSON text (output type `string`), `with_on_error(OnError::Skip)` leaves failed elements out of the output (their `for_each_item_failed` event reports them), `with_max_parallel(n)` at a time via `buffer_unordered` within one task; results in input order; the first failing element fails the node with `for_each '<id>', element <i>: <error>` and elements that have not started do not start. Each finished element (output or skipped) is saved under `for_each::progress_key(node_id)` = `grauwolf.for_each.<id>` with `save_progress()` (ADR-0052); a resumed run runs only the missing elements and removes the entry at the end. Events `for_each_item_starting/completed/failed { node, index (, error) }`. `for_each::for_each::<I, O>(config, node_id)` for typed code.

Run lifecycle (ADR-0116): `run_lifecycle::AgentRun` is the one sequence of an agent run for the interpreter and generated code: `agent_starting` → (conversation history loaded first) → memory recall → `inject_knowledge` → graph run → output as JSON → automatic remember → conversation saved → exactly one of `agent_completed`/`agent_failed` (usage, cost). Options: `with_memory(memory, recall, remember)`, `with_knowledge(ctx)`, `with_conversation(store, id)`, `with_attachments(..)`, `with_checkpoints(store, run_id)` (the input is kept in the storage for the remember step; progress saver), `with_caller(id)` (the SPIFFE ID reported as `caller` in `agent_starting`, ADR-0109; `RunHandles.caller` for generated code), `with_trace_parent(Some(TraceParent { traceparent, tracestate }))` (the caller's W3C trace context, raw header values, reported as `trace_parent` in `agent_starting`; `RunHandles.trace_parent` for generated code; ADR-0123), `resumed()` (no recall, knowledge, conversation or attachments; the graph run resumes). `run(&mut ctx, |ctx, observer| Box::pin(..))` takes the graph run as a function returning `Result<O: Serialize, EngineError>`; `RunError { Graph, Output, ChatHistory }` – every one is reported as `agent_failed`. `AgentRun::remember_compressed` hands the memory to the context (`set_fact_memory`) so the durable facts of a compression are stored by one code path for the interpreter and generated code; `adopt_run` stays with the caller that builds the context. Fast unit tests in the module (fake LLM, memory, knowledge, chat store).

Approvals (ADR-0061, ADR-0119): `approval::ToolApprover` (asynchronous decision on a tool call) and `approval::ApprovalGate { tools, approver }`, the interceptor that asks the approver for the listed tools and, without one, refuses with `tool '<name>' needs an approval that nobody can give here`; shared by the interpreter and generated code.

Run handles (ADR-0119): `run_handles::RunHandles { prices, budget, frame_sink, approver, conversation, attachments, checkpoints, resume }` is what a caller brings to a run of generated code – the counterpart of the interpreter's `RunExtras`: `resume_state()` loads the checkpoint of a resume (`StartError::NoCheckpoint` with the interpreter's text; a conversation together with checkpoints is refused), `context(executor, model, prompt, state, limits, approval_tools)` builds or restores the context (`limits.max_cost` without prices → `StartError::CostLimitWithoutPrices`) with prices, the budget (`merged_budget`: the caller's fields win over the spec's `limits`, as in the interpreter), frame sink, run handle for sub-agents and the `ApprovalGate` for the listed tools, `start(input, state)` makes the `AgentRun` (conversation, attachments, checkpoints, `resumed()`), and `RunHandles::run_graph(run, ctx, typed graph, input, state)` runs or resumes the typed graph in it. Test `tests/run_handles.rs`.

## Where things live
- `context.rs`: `AgentContext` (public API, thin coordinator over the components below; ADR-0108 stage 5, done). Its methods delegate; `request_llm_with`, `request_llm_structured` (retry loop), `snapshot`/`restore`/`fork`/`apply`/`absorb` stay here because they combine several components.
- `accounting.rs`: shared usage/cost/tool-call counters and `Budget`, prices, tokenizer (add usage, check budget, claim a tool call); forks share the counters.
- `storage.rs`: agent storage map and the progress-saver hook (store, load, remove, save progress); forks copy the values and get no hook.
- `conversation.rs`: history and the pending attachments of the run's input (append takes them for the next user message without its own; replace, attach); forks copy both.
- `model_selection.rs`: active model and the stack of subgraph models (set, enter/leave scope, `outermost()` for snapshots); forks copy it.
- `tool_access.rs`: registry, tool-subset/build-permission scope stack and self-tool settings; `is_allowed` is the pure permission logic, `descriptors()` the offered tools; forks copy the stack (the registry's shelf stays shared). `tool_execution.rs` asks `is_allowed`.
- `tool_execution.rs`: `ToolExecution`, a borrowed view (tool access, bus, accounting, storage) that runs one tool call: interceptor verdict (with the tool-call limit), `tool_call_starting`, section check, `claim_tool_call`, the call (stateful tools under the storage lock, state kept only on success), `after_tool_call`, `tool_call_completed`; `AgentContext::execute_tool` builds the view and delegates. Unit tests without a `PromptExecutor`.
- `event_bus.rs`: installed features and interceptors (install, intercept, `emit`, `prepare` of a request, `finish` of an answer, `judge_tool_call` with the before/approve hooks, `after_tool_call`, the moderation-text interception); `MODERATION_PROMPT_ID` lives here; forks copy the lists.
- `llm_gateway.rs`: `LlmGateway`, a borrowed view (executor, model selection, bus, accounting, frame sink; not the history) with the request paths (`request`, `request_streaming`, `request_structured`, `request_json`, `request_choices`, `moderate`), `with_fallbacks`, the LLM call events and `forced_call_instruction`/`makes_call`. Callers pass the prompt and append the answer; `AgentContext::gateway()` builds the view. Unit tests use a small in-module `LlmClient`.
- `facts.rs`: `extract_facts`, `request_fact_lists` (structured `{ facts }`/`{ facts, durable }` request) and the `FACT_*`/`DURABLE_FACTS` instructions; free functions over `LlmGateway`; the caller checks the budget.
- `compression.rs`: `HistoryCompression`, its helpers (`transcript`, `keep_from`, `facts_message`) and `compress(conversation, gateway, fact_memory, strategy)` (summarize, keep last, facts; durable facts to the `FactMemory`); `AgentContext::compress_history` checks the budget and delegates.
- `decision.rs`: besides the decision types and answer rules, `decide_with_model(gateway, budget, decision, state)`, the LLM side of the `llm` decider (the budget result is passed in so the model name is checked first, as before).
- Moderation lives in `llm_gateway.rs` (`moderate`); `AgentContext::moderate` is a one-line delegation.
- Tests: each component and feature module has in-module unit tests with a small `LlmClient`; grauwolf-test is for `tests/` only.

## Invariants
- No export technology (OTel, files) – only events and the pipeline.
- `Feature::trace_headers(call)` (default empty; ADR-0123) lets a tracing feature give the W3C headers of the span that makes a call out of the run: `AgentRun` uses the headers of the enclosing scope as `trace_parent` when none was given (a sub-agent in the same process continues its caller's trace); `ToolExecution` asks for the tool call's ID and wraps the call in `grauwolf_tools::with_trace_headers`, `run_agent_step` asks for the innermost open step. The headers are plain strings; the feature (grauwolf-otel) does the OpenTelemetry part.
- Events and ExecutionState are serde-serializable.
- No tokio: time and parallelism only through the ports `Clock`/`Spawn`; concurrency within one task (`join_all`) is allowed.
- The environment enforces the tool set of the active subgraph (implemented in `AgentContext`).
- Use grauwolf-test only in integration tests (`tests/`).
