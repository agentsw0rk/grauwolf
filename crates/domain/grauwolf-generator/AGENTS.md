# grauwolf-generator

**Layer:** `domain` · **Status:** `--service` crates enable `grauwolf/service`, `grauwolf/otel` (ADR-0123) and `grauwolf/credentials` (ADR-0110: `grauwolf-k8-ops agent deploy` always mounts a `[credentials]` configuration; without the feature the service refuses to start). The generated manifest enables the facade feature `pgvector` only when `knowledge.store` is `postgres` or the memory has a `vector_store` (ADR-0106; snapshot `pgvector_knowledge_cargo_toml`); `companion_paths` (the pure answer to "which paths belong to a spec", used by `grauwolf_host::agent_tree` for every node, ADR-0115) names the memory `store` file only when there is one; `companions` is the same list with the JSON pointer and kind (`CompanionKind`) of each field, for the references grauwolf studio shows (ADR-0126). The generated manifest enables the facade feature `bedrock` only when `spec.providers()` contains `bedrock` (ADR-0105). Code in graphs (ADR-0102, F14.14): the artifacts of `AgentSpec::code_pieces()` are embedded like tools (`tools/<piece name>.wasm`, `grauwolf-sandbox` and `grauwolf-tools` in the manifest) and run as sandboxed modules, not as native code: the library defines `code_module(name, bytes)` (loaded once per process) and the graph functions use `grauwolf_agents::code::code_node_typed` for `code` nodes and `TypedGraphBuilder::edge_with(condition, transform)` for edges with `on_code` or `transform` – the same functions as the interpreter, so behavior and isolation match (`examples/specs/review_router.json` in the equivalence test); with `GenerateOptions::tool_sources` every piece needs a source crate (`MissingToolSource`) and gets a `tools/tools.json` entry with its `kind`. A spec whose `run_command` is in shell mode with `approve_each_call` (default) is generated like any other: the tools of `AgentSpec::approval_tools()` are gated by the approver of the run's handles, refused with the interpreter's text without one (ADR-0099, ADR-0119). The facade dependency of a generated crate lists `git`, `fetch`, `command` and/or `atlassian` besides `mcp`, `builtin` when the spec uses tools of these groups (`builtin_features`; ADR-0108); `--full-facade` takes every default feature. Models with `temperature`/`think` as `.with_temperature(..)`/`.with_think(..)` (`model_expr`, `set_model` → `switch_model`; ADR-0097; snapshot `sampling_echo_lib`, `sampling_echo.json` in the equivalence test). Service (ADR-0093, F14.1): `generate_crate_with(spec, dep, artifacts, &GenerateOptions { service, full_facade })` (`dockerfile: Some(DockerfileOptions { builder_image, expected_builder_version })` also writes `Dockerfile` and `.dockerignore` for an offline build in the builder image, implies `service`, ADR-0096; `expected_builder_version: Some(v)` adds a first build step that fails unless the builder's `GRAUWOLF_VERSION` is `v`, `None` omits it; `default_builder_image(version)`; `full_facade`: the facade with its default features instead of the list the spec needs, one dependency graph for all specs, ADR-0096) (`generate_crate` = default options) additionally writes `src/main.rs` (one call of `grauwolf::service::main(<crate>::SPEC_JSON, closures over `provision` and `run_provisioned`)`), the Cargo feature `service = ["app", "grauwolf/service", "grauwolf/otel"]` (`GRAUWOLF_OTEL` switches tracing on at run time, ADR-0123; a full facade has the feature anyway) and `[[bin]] name = "agent"` with `required-features = ["service"]` (fixed binary name; snapshots `echo_service_*`); end-to-end test `generated_services_authenticate_callers_by_spiffe` (the same binary with `GRAUWOLF_SPIFFE=1` against `FakeWorkloadApi`: mapped client ok, unmapped `403`, `caller` in `agent_starting`; shares the build directory, so the tests take turns) and `generated_services_export_spans_and_continue_the_callers_trace` (`GRAUWOLF_OTEL=1` against a wiremock collector: spans arrive after SIGTERM, in the trace of the request's `traceparent`; the protobuf is searched for ids and names, not decoded) and `generated_services_answer_health_and_run` (builds the binary, `/health`, `/run`, A2A on `A2A_PORT` with `A2A_BASE_PATH`, mocked Ollama; dev dependency reqwest). Decisions (ADR-0100): with `decider: system_one` nodes (`AgentSpec::uses_system_one()`) the entry points get a `run_with_decider(.., decider: Option<Arc<dyn Decider>>)` step before `run_observed` (`run_observed` then takes `decider` after the memory argument; `ctx.with_decider`); `run_provisioned` takes the decider from `provisioned.decider()` (provisioning fails before the run without `RKEV_BASE_URL`), and the manifest enables the facade feature `systemone` only for such specs; `ticket_router.json` (the `llm` decider) is in the equivalence test, plus `generated_crates_route_by_the_decider_they_are_given` for `system_one` (also as an app without a service). Models with `fallbacks` as `LlModel::new(..).with_fallbacks(vec![..])` in `model()` and subgraph scopes (`model_expr`, ADR-0088; `set_model` with `fallbacks` → `nodes::switch_model`; `llm_moderate` with `fallbacks` in the model; `fallback_echo.json` and `switching_fallback.json` in the equivalence test). Events (ADR-0084 addendum): the core of each crate is `run_observed(executor, input, [external,] [memory,] features)` – it installs the features and makes one call of `grauwolf_agents::run_lifecycle::AgentRun` (`with_memory`, `with_knowledge`) whose graph run is `TypedGraph::run_observed` – the lifecycle reports `AgentStarting`, does the memory steps and reports `AgentCompleted`/`AgentFailed` with usage and cost, the same code as the interpreter (ADR-0116; an output that cannot be converted → `AgentFailed`); `run` → `run_with_tools` → `run_with_memory` → `run_observed` each pass on empty values; `serde_json` is always in the manifest; the equivalence test compares output **and** event sequence for every case (`tests/support/event_log.rs`). `generate_lib(spec)` produces `graph()`, `model()`, `prompt()`, `run()`; the output is syn-checked and formatted with prettyplease (`GeneratorError::InvalidCode`). `generate_crate(spec, dep, artifacts)` returns a self-contained crate in memory (Cargo.toml + lib.rs, tool artifacts as `binary_files` under `tools/`; `tools()` loads them in grauwolf-sandbox; snapshot tests). Equivalence test interpreter ⇔ generated crate on the corpus with JSON inputs, also for named types (`tests/equivalence.rs`, builds via cargo in `<CARGO_TARGET_DIR or target>/generated-equivalence`). Templates in `templates` (`node(kind, params)` and `condition(kind, params)` → Rust expression, e.g. `llm_request_structured::<Ticket>`, `compress_history_keep_last::<grauwolf_prompt::ToolResult, 1>`, `compress_history_facts::<T, KEEP>` (ADR-0076), `execute_multiple_tools` with `sequential: true` → `nodes::execute_tools_in_order`, `on_history_longer::<_, 2>`, `on_history_tokens_above::<_, 4000>`; `token_trimmer.json` in the equivalence test, ADR-0087; `decide` becomes `grauwolf_agents::nodes::decide::<T>("<node id>", "<params as JSON text>")` via `templates::node_for(id, kind, params)`, `on_decision` a closure over `grauwolf_agents::conditions::on_decision`, ADR-0100) with a conformance test against the catalog (example parameters). Named types (`types`, ADR-0022) become structs (serde + schemars; `string`/`integer`/`number`/`boolean`/`array`; non-required fields as `Option`); `input`/`output` determine the signature of `graph()` and `run()`; every subgraph becomes `pub fn subgraph_<name>()` (typed by its signature) and is built before the builder; nodes of kind `subgraph` attach it via `g.subgraph(..)` with a `ToolSubset` scope, with their own model as a `SubgraphScope` (ADR-0034, ADR-0043; `two_models.json` in the equivalence test); nodes of kind `parallel` become `grauwolf_agents::parallel::parallel::<I, O>(vec![Branch::new(name, subgraph_<name>()?.into_graph())…], Merge::…)` (ADR-0045; `perspectives.json` in the equivalence test); `remember_task.json` (agent storage `store`/`load`, ADR-0044) in the equivalence test; schemas that cannot be represented → `GeneratorError::UnsupportedType` with a JSON pointer. Every struct implements `grauwolf_agents::Structured` with the schema from the spec (ADR-0031); `triage.json` (structured LLM response), `relay.json`, `streaming_echo.json`, `parallel_calculator.json`, `subgraph_calculator.json`, `compact_calculator.json`, and `draft_and_summarize.json` (several tool calls per response) run in the equivalence test. Nodes of kind `plan` become `grauwolf_planner::plan_node(Arc<LlmPlanner>, max_iterations)` over `subgraph_<name>()?.into_graph()` (tool subset as `with_step_scope`, `with_critic()`; the crate then depends on grauwolf-planner, ADR-0039); `planner.json`, `react_calculator.json` (strategy `react`), and `verified_calculator.json` (strategy `verified`: rejected first, then accepted) run in the equivalence test. The sequential strategies also run with two tool calls in one answer (`execute_tools_in_order`; extra cases for `limited_calculator.json` with the per-call tool limit, `react_calculator.json` and `verified_calculator.json`; ADR-0041 addendum). External tools (`AgentSpec::external_tools()`: MCP, knowledge, sub-agents, built-in; ADR-0050) become `pub const EXTERNAL_TOOLS`, `run_with_tools(executor, input, external)`, and `tools(external)` (checks that all are provided; takes only the declared ones); `run` calls `run_with_tools` without external tools; `notes_reader.json` (built-in `read_file`) runs in the equivalence test (both sides in one Tokio runtime). Automatic memory (`auto_recall`/`auto_remember`, ADR-0069, ADR-0084): `run_with_memory(executor, input, [external,] memory: Option<Arc<dyn FactMemory>>)` through the run lifecycle (`AgentRun::with_memory`, ADR-0116), in the same order as the interpreter; `remember_compressed` (ADR-0079) emits `run.remember_compressed()` on the run lifecycle (test `asks_the_run_lifecycle_to_remember_compressed_facts_only_when_the_spec_does`); `run`/`run_with_tools` call it without memory; recall and remember are verified by fast unit tests of the lifecycle in `grauwolf-agents` (ADR-0116; the former memory and knowledge equivalence cases are gone). Run handles (ADR-0119): the core of all entry points is `run_handled(executor, input: Option<I>, [external,] [memory,] [decider,] features, handles: RunHandles)` (`run_observed` calls it with `RunHandles::default()`): it asks `handles.resume_state()`, builds the context with `handles.context(.., limits, approval_tools)` (prices, caller budget over the spec's limits, frame sink, `ApprovalGate` for `AgentSpec::approval_tools()`), starts the lifecycle with `handles.start(..)` (conversation, attachments, checkpoints, resume) and runs the graph with `RunHandles::run_graph`; the same code as the interpreter's run options. With the feature `app`, `run_provisioned(&provisioned, input, RunOptions)` and `resume_provisioned(&provisioned, store, run_id, RunOptions)` go through `RunOptions::handles(provisioned.prices())`. Every crate contains `SPEC_JSON` (`AgentSpec::to_json`) and, behind the Cargo feature `app`, `provision(base_dir, ProvisionOptions)` (one `ProvisionedAgent::new` call, with the `AgentLoader` as sub-agent supplier when the spec has `agent_tools`), `run_provisioned(&provisioned, input, RunOptions { user, features })` (tools via `provisioned.tools_for(user)`, automatic memory via `provisioned.run(user)?.facts()`, events to the features via `run_observed`), `run_app(base_dir, input)` (with the process environment) and `run_app_with(base_dir, input, provision_options, run_options)` (ADR-0114). The facade is optional without default features (providers `ollama`/`openai`/`anthropic`/`gemini`; with external tools `mcp`+`builtin`; with sub-agents `sandbox`+`a2a`), `ProvisionedAgent::new` (executor, external tools, memory; sub-agents through `AgentLoader::for_provisioning`, cache `<base_dir>/.grauwolf/tools`, which takes the observer and the sub-agent features from the `ProvisionOptions`, ADR-0094; ADR-0084, ADR-0114). End-to-end test `generated_apps_provide_providers_tools_and_memory_themselves` (`app_assistant.json` against a reproduced Ollama, as user `anna` with an event log). Only in the interpreter (→ `GeneratorError::Unsupported`): `tools_dir` (ADR-0074) and `self_tools` (ADR-0075); `limits.max_cost` is generated into the limits of the run (ADR-0119: prices come with `provisioned.prices()`, the price table of `GRAUWOLF_PRICES` or `ProvisionOptions::with_prices`; without one provisioning fails); `limits.max_steps` → `g.max_steps(n)` in every graph function; `max_tokens`/`max_tool_calls`/`max_prompt_tokens` → `ctx.with_budget(..)` in `run_observed`. `goap` nodes (ADR-0070): step graphs from the subgraph functions (attached to a subgraph node with scope), planner via `grauwolf_planner::goap::fact_planner` with the parameters as JSON text, node via `planner_node`; dependencies `grauwolf-planner` and `serde_json`; actions with an `agent` get no step graph (the sub-agent comes from the loader like for `agent` nodes); equivalence cases `goap_baker.json` and `review_loop.json` (agent and subgraph actions, mocked Ollama; snapshot `review_loop_lib`). A source map was discarded (ADR-0053); types that cannot be represented are already reported by the spec check (`UnsupportedSchema`, ADR-0080); `UnsupportedType` remains as a safeguard.

Tool packages (ADR-0107): `GenerateOptions::package_tools` (`ResolvedTool`s of the spec's `tool_packages`, resolved by the caller) are embedded like local tools (`tools/<name>.wasm`, `include_bytes!`); the generator works on a copy of the spec in which they are tools without code and `tool_packages` is empty, so the crate (including `SPEC_JSON`) has no reference to a registry and the image build stays offline; a spec with `tool_packages` and no `package_tools` → `GeneratorError::UnresolvedPackages`.

Tool sources (ADR-0095, F14.5): `GenerateOptions::tool_sources: Some(Vec<ToolSourceCrate>)` (the CLI fills it with `grauwolf_toolbuild::guest_crate`; the generator has no template of its own) writes `tools/<name>/Cargo.toml`, `tools/<name>/src/lib.rs`, the manifest `tools/tools.json` (`ToolSourcesManifest`) and a std-only `build.rs` that panics naming `grauwolf tools build .` while a `tools/<name>.wasm` is missing, instead of the modules (`binary_files` stays empty, artifacts are not looked at; a tool without entry → `GeneratorError::MissingToolSource`). `lib.rs` embeds `tools/<name>.wasm` unchanged. With `dockerfile`, the `Dockerfile` copies `tools/` first and runs `grauwolf tools build . --cache /tmp/tool-cache` in its own layer before `COPY . .`. Snapshots `tool_sources_*`. Without `tool_sources` nothing changes.


Skills (ADR-0103, F14.16): `skills` make `load_skill`/`read_skill_file` external tools (`AgentSpec::external_tools()`, so `EXTERNAL_TOOLS` and the facade features `mcp`+`builtin` follow); with skills `run_body` builds the registry first (`let registry = tools(external)?;`) and extends the prompt with `registry.prompt_addition()` (`Prompt::extend_system`) – the same system prompt as the interpreter. The skill directories are not embedded: `SPEC_JSON` names them and `provision` reads them from `<base_dir>/<dir>` through the host; the CLI copies them to `app/` and rewrites git sources into local directories before generating (`grauwolf-cli` `spec generate --dockerfile`). Equivalence case `skill_writer.json` (`load_skill` call and the `skill_loaded` event; `GRAUWOLF_EQUIVALENCE_ONLY=<spec file>` runs a single case).

Node `for_each` (ADR-0101): `graph_function` builds `grauwolf_agents::for_each::ForEach` from `ForEachParams` (agent body, or subgraph body with its scope; `on_error`, `max_parallel`, text output) and emits `for_each::for_each::<I, O>(config, "<id>")`; `array<T>` types are `Vec<T>` (`types::type_ref`). Slow equivalence test `generated_flows_run_agent_and_for_each_nodes_like_the_interpreter` runs `examples/specs/topic_report.json` as a generated app against a mocked Ollama. Node `agent`: `templates::node_for` emits `nodes::agent_step::<I, O>("name")`; `array<T>` is `Vec<T>` in templates (ADR-0101).

`generate_lib_limited(spec, limits)` (ADR-0124): `generate_crate_with` passes the limits of package tools that ask for some; those tools are loaded with `runtime.instantiate_limited(…, &grauwolf_tools::ToolLimits { … })` in the generated `tools()`, all others as before (`generate_lib` = no limits, unchanged output).


## Purpose
Generates a Rust crate from an AgentSpec (`Cargo.toml`, `src/lib.rs`, tool artifacts under `tools/`).

## Features / ADRs
E13 (F13.6–F13.8, F13.13; source map for F13.9 discarded, ADR-0053), ADR-0022, ADR-0031, ADR-0034, ADR-0039, ADR-0043, ADR-0044, ADR-0045, ADR-0050, ADR-0069, ADR-0070, ADR-0074, ADR-0075, ADR-0076, ADR-0078, ADR-0084, ADR-0093, ADR-0100

## Allowed dependencies
- grauwolf crates: grauwolf-spec, grauwolf-codegen, grauwolf-tools (`ToolArtifact`); dev (equivalence test): grauwolf-agents (memory port), grauwolf-interpreter, grauwolf-graph, grauwolf-llm, grauwolf-test, grauwolf-sandbox, grauwolf-toolbuild, grauwolf-builtin-tools, grauwolf-spiffe (feature `testing`: the fake Workload API and test CA for the SPIFFE service test) – adapters only as dev dependencies
- External: thiserror, serde_json (reading the types' schemas); dev: reqwest, futures-executor, futures-util, insta, tokio, wiremock

Other dependencies only after checking against [ADR-0016](../../../docs/adr/0016-layered-architecture.md).

## Invariants
- Generated code uses the typed builder from grauwolf-graph and generates structs for spec types (ADR-0022).
- Output is deterministic (snapshot tests).
- Does not execute code itself; `cargo check` starts grauwolf-cli.

## Knowledge as context (ADR-0113)
A spec with `knowledge.inject` takes external tools even when it offers none (`EXTERNAL_TOOLS` may be empty; `run_with_tools`, `run_provisioned` provide them): `run_observed` takes the `KnowledgeContext` of the provided search tool by its name (`grauwolf_tools::knowledge_context_of(&external, "<knowledge.tool>")`, the error text of a missing tool as in the interpreter) before `tools(external)` and passes it to the run lifecycle with `.with_knowledge(..)`, like the interpreter (ADR-0116). Tests: `generate.rs` (structure; the order of recall and injection is a fast unit test in `grauwolf-agents`, `run_lifecycle`).

Facade features of built-in groups (ADR-0117): `builtin_features` reads `BuiltinToolsSpec::groups()` and maps each group with the exhaustive `group_feature` (the domain table has no Cargo features, ADR-0016); the features keep the order `git`, `fetch`, `command`, `atlassian`.

No unused imports (ADR-0119): `generate_lib` imports `grauwolf_agents::events::AgentEvent` only when the generated code names it (test `imports_agent_event_exactly_when_the_generated_code_uses_it`); generated crates build without warnings.
