# grauwolf-git

**Layer:** `adapters` · **Status:** extracted from grauwolf-tools-git in ADR-0107 stage 3 (the transport unchanged), plus `fetch_files(&FetchRequest, folder?, include) -> Fetched { commit, files }` (blocking; call it from `spawn_blocking`): fetches one commit into a bare scratch repository in the temp directory (`Wanted::Commit` full or abbreviated ≥ 7 hex, `Tag`, `Branch`; shallow first, then the branch and tag tips; the commit must be reachable from one), resolves it to the full 40-hex commit, reads the blobs below `folder` for which `include(relative path)` holds (symbolic links and submodules skipped, at most `MAX_FETCHED_BYTES` = 16 MiB) and removes the scratch directory; errors are `GitError(text)` with the token masked. Feature `test-git-server`: `testing::TestGitServer` (smart-HTTP upload-pack over a bare repository on disk, any path, optional required token, records requests with their `Authorization` header, `serve(listener, …)` to restart on a port, `stop()`; no shallow support, so clients fall back), the example `serve_folder` (serves a folder as a repository for live checks), `commit_files(path, branch, message, files)` and `tag(path, name, commit, annotated)` build the repository with libgit2. `init_libgit2()` (process-wide libgit2 settings, once: user/system configuration never read, owner validation off) and the own smart-HTTP transport: `register()` (once per process for `http`/`https`), `with_settings(Settings { token, origin, timeout }, call)` (per-call settings in a thread-local around one blocking libgit2 call), `origin_of(url)`. `GET …/info/refs?service=…`, `POST …/git-upload-pack|git-receive-pack`, no redirect followed (libgit2's redirect code crashes on a `Location` without query), `Authorization: Basic` (user `x-access-token`) only to the scheme and host in `Settings::origin`.

**SSH signatures (ADR-0107 stage 4), module `sshsig`:** `Fetched.objects` (`SignedObjects`: the raw commit object and, for an annotated tag that was asked for, the raw tag object). `AllowedSigners::parse(text)` reads git's `gpg.ssh.allowedSignersFile` format (`principals [namespaces="…"] keytype key [comment]`; `*`/`?` globs; other options such as `cert-authority`, `valid-before` and negated principals are errors with the line number; ed25519 and ecdsa-p256 keys), `verify_objects(&objects, commit_id, tag_name, &signers)` checks that the objects are that commit (SHA-1 of the object) and that tag (headers `object`/`tag`), then verifies the SSH signature (`gpgsig` header of the commit, block appended to the tag message; namespace `git`) of the tag first, else of the commit, against the signers (key, namespace, and the committer or tagger email against the principals) → `Verified { fingerprint, signed }` or `SignatureError::{Unsigned, Invalid}`. `commit_signature`/`tag_signature` extract the signed data. GPG and X.509 signatures are `Invalid` ("not an SSH signature"). Test kit: `testing::TestSigner` (ed25519, `allowed_signers(principals, namespaces)`, `fingerprint`), `commit_files_signed`, `tag_signed` – no `ssh-keygen` needed.

**Local checkouts (ADR-0124):** `checkout_of(dir) -> Option<Checkout { remote, commit }>`: the repository a folder lies in (`Repository::discover`), `HEAD`'s commit and the URL of `origin` with any credentials removed; `None` outside a repository or before the first commit. Used by `tools pack` for the `source`/`revision` annotations.

**Build sources (ADR-0129):** `build_source(folder) -> Result<BuildSource { remote, branch, commit, path }, String>`: what Kaniko clones to build a harness project – `origin` without credentials, the branch `HEAD` is on (`refs/heads/…`), its commit and the folder relative to the repository's root; an error (with the folder) outside a repository, before the first commit, on a detached `HEAD`, without `origin`, or when the folder has changes that are not committed (untracked files included; they are listed – Kaniko builds the commit), or when the commit is not on `refs/remotes/origin/<branch>` (equal to it or an ancestor, as of the last fetch). Test `tests/build_source.rs`.


**Project repository (ADR-0130), module `project`:** `ensure_project_clone(dir, remote_url, branch, Option<&Credentials { username, token }>) -> Result<ProjectClone { dir, branch }, String>` (blocking): a missing or empty `dir` is cloned from `remote_url` (on `branch` if the remote has it; an empty remote or one without the branch is fine: `HEAD` is put on the unborn `refs/heads/<branch>`, the first commit creates it). https credentials go through the crate's own transport: the operation runs under `with_settings` with the token and the origin of the remote URL, so the token is sent as `Authorization: Basic` (user `x-access-token`; `Credentials.username` is not used) to that origin only, never into the URL, `.git/config` or a message. GitHub accepts a personal access token that way. There is no libgit2 credentials callback. A `dir` that already is a clone (`.git` in it) is kept as it is if its `origin` equals `remote_url` (credentials in URLs ignored), else the error names both URLs; nothing is fetched. A `dir` with files but no `.git` is turned into a clone: `git init`, `origin`, `branch` fetched if the remote has it (then the local branch, `HEAD` and the index are at its tip, the files stay and show up as changes for the first commit). Test `tests/project.rs` (local bare repository as remote; `TestGitServer` with a token for clone, commit and push over http, and the 401 without the token).

`commit_folder(dir, folder, message, author_name, author_email) -> Result<Option<String>, String>`: stages every change below `folder` (relative to the clone's root; new, changed and deleted files) and nothing else (the index is first reset to the last commit), commits on the current branch (an unborn branch gets its first commit) and returns the commit id, `None` when the folder's tree did not change.

`push(dir, branch, Option<&Credentials>) -> Result<(), String>`: pushes `refs/heads/<branch>` to `origin` (credentials through the transport's settings, like `ensure_project_clone`); a refusal (non fast-forward, rejected by the server) is an error with libgit2's or the server's message. libgit2 moves `refs/remotes/origin/<branch>` to the pushed commit, so `build_source` accepts the folder afterwards.

## Purpose
Everything shared by the users of libgit2: the git tools and the tool packages from git repositories (ADR-0107).

## Features / ADRs
E14 F14.17, ADR-0104, ADR-0107, ADR-0108

## Allowed dependencies
- grauwolf crates: grauwolf-spiffe (the client identity in the transport; `testing` with the test server)
- External: git2 (vendored libgit2, no `https`/OpenSSL; needs a C compiler), reqwest (blocking), ssh-key (SSH signatures, ed25519 and p256); feature `test-git-server`: axum, base64, tokio

Other dependencies only after checking against [ADR-0016](../../../docs/adr/0016-layered-architecture.md).

## Invariants
- The token never appears in a URL, error or log; it goes only to the scheme and host of `Settings::origin`; no redirect is ever followed.
- Nothing is left on disk after a fetch; nothing here knows what a tool package is.
