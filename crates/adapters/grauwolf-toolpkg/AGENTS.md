# grauwolf-toolpkg

**Layer:** `adapters` · **Status:** Stages 1 to 4 of ADR-0107 (pull, packing, push, git sources, policy and signatures), on top of grauwolf-oci since stage 3b of ADR-0108. The package format and everything that knows what a tool package is: the media types (`ARTIFACT_TYPE`, `CONFIG_TYPE`, `MODULE_TYPE`, `SOURCE_TYPE`, `TITLE_ANNOTATION`), `Package` (verified manifest + modules + source) assembled from an OCI manifest and its blobs, `PackedPackage` (OCI manifest + blobs; `new` from manifest, modules and optional source layer; derefs to `grauwolf_oci::OciImage`, which `RegistryClient::push` takes; `write_layout`/`read_layout` for an OCI image layout directory, `read_layout` also checks the package media types; `package()` assembles it like a pull) and `source_archive` (the source layer: ustar in gzip with stored deflate blocks, written by hand, sorted, fixed mtime/uid/gid – reproducible), `PackageCache` (`<tool cache>/packages/sha256-<hex>/`, manifest + blobs, verified on every load), `Lockfile` (`grauwolf.lock`, JSON, sorted), `PackageResolver::pull(ref)` and `resolve(spec, lock_path)` (→ `Vec<ResolvedTool>`, selection and renaming, `--locked` via `with_locked`). **Git sources (stage 3):** `with_git(token, Arc<dyn ModuleBuilder>)` enables them; an entry (`GitSource`, key `git+<url>[//<path>]@<rev | tag:<t> | branch:<b>`) is fetched with `grauwolf_git::fetch_files` (`grauwolf-tools.json` and `src/**` of the folder at the commit), **always built from the sources** with the `ModuleBuilder` (`prepare`, `build(&ToolSpec)`; the facade implements it with grauwolf-toolbuild) through `pack_sources(manifest, read, label, builder)` (shared with `tools pack`) and stored like an OCI entry (`PackageCache::load_git`/`store_git`: `<tool cache>/packages/git-<commit>[-<16 hex of sha256(path)>]/`, manifest + blobs, verified on every load, damaged = error). `Lockfile.git` (key → `LockedGit { commit, modules }`, section absent without git entries); a locked entry is fetched by commit, never by tag/branch; a full-commit `rev` or a locked commit is looked up in the cache before any network access; module hashes are compared on every resolve (a rebuild on another toolchain fails the comparison unless the cache entry exists). `--locked` fails before any request when an entry is missing or stale. Errors: `PackageFetchError::Git { entry, reason }` (token never in them). The registry client, credentials and the image layout reader/writer live in grauwolf-oci; this crate re-exports `RegistryClient`, `RegistryAuth`, `REGISTRY_AUTH_ENV`, `DockerConfig`, `default_config_path` and `sha256_digest` so that the facade and the CLI keep their paths, and maps `OciError` into `PackageFetchError` (same variants plus the package ones). Feature `test-registry` (forwards `grauwolf-oci/test-registry`): `testing::TestRegistry` (wraps the oci registry, derefs to it, adds `push(repository, tag, &TestPackage)`), `TestPackage` and `PONG_MODULE` (WAT module of tool ABI v1) for tests of this and other crates; the example `serve_test_package` serves one package for live checks.

**Policy (stage 4):** `Policy` = `ToolPolicy` rules (grauwolf-tools) plus the loaded public keys; `Policy::load(path)` reads the policy file and the key files it names relative to itself (PEM, several blocks per file allowed; errors name the file), `PackageResolver::with_policy(policy)` checks every package at the start of `pull` (OCI) and `git_package` (git) – before the cache, the lockfile or the network are looked at, so cached and locked packages are refused too (`PackageFetchError::Policy`, text names the package and the rule).

**OCI signatures (stage 4):** with `require_signatures`, `pull` verifies a cosign signature (grauwolf-oci `cosign`, identity `registry/repository`, digest of the package manifest) against `Policy::oci_keys`; the signatures are stored with the cache entry (`signatures.json`, `PackageCache::load_signatures`/`store_signatures`), tried first (so a changed key set applies offline) and fetched from the registry when they do not satisfy the policy; an entry cached earlier gets no fetch under `--locked` (error that says so), a freshly pulled one does. A network error with stored signatures present reports the stored verdict. `PackageResolver::inspect(ref, extra_keys)` (for `tools inspect`) applies the allowlist only and returns the package with a `SignatureStatus` (`Signed { fingerprint }`, `Unsigned`, `Invalid(reason)`, `Unchecked { signatures }` without any key; fresh from the registry, else the stored signatures); `cosign` is re-exported. Errors are `PackageFetchError::Policy` (`unsigned`, `signature invalid`, no `oci_keys`).

**Git without a spec:** `PackageResolver::pull_git(&GitSource)` (policy, fetch, signature check, build, cache – `git_package` without a lock; returns package and commit) and `inspect_git(&GitSource, extra_signers)` for `tools inspect` (allowlist only; fetches the commit and the manifest, never builds; `GitInspection` with commit, manifest, cached `Package`, `GitSignatureStatus` = signed/unsigned/invalid/unchecked against the policy signers or `extra_signers`; a full `rev` cached with its objects needs no network).

**Git signatures (stage 4):** `Policy::git_signers()` (`AllowedSigners` of `git_allowed_signers`, read relative to the policy file by `Policy::load`, or `with_git_signers`). With `require_signatures`, `git_package` checks the commit of every git entry with `grauwolf_git::verify_objects` **before anything is built**: `rev`/`branch` need a signed commit, `tag` a signed annotated tag or else a signed commit (a lightweight tag on an unsigned commit is refused). The raw objects are stored with the cache entry (`commit.object`, `tag.object`; `PackageCache::load_git_objects`/`store_git_objects`) and tried after the freshly fetched ones, so a changed policy applies offline and `--locked` works without network. When neither passes and no objects were just fetched, they are fetched again (`Wanted::Tag` for tag entries, else `Wanted::Commit`; the commit must be the same) – `--locked` forbids that and the error says so. A git entry under `require_signatures` without `git_allowed_signers` is a `PackageFetchError::Policy`.

**Git skills (ADR-0103, F14.16):** `PackageResolver::resolve_skills(spec, lock_path)` → `Vec<ResolvedSkills { index, key, commit, dir }>` for the git sources of `spec.skills` (`GitSource::from_skill_source`, same key form as git packages; local sources are skipped). Same rules as git packages: policy (`allowed_git_hosts`), `require_signatures` with the SSH allowed signers (checked before anything is stored, objects stored with the entry, applied again offline), a locked source is fetched by commit, a full `rev` or a locked commit is looked up in the cache first, `--locked` fails before any request when a source is missing or stale. Everything below the folder is fetched (`Include::All`) and stored in the cache entry `skills-<commit>[-<16 hex of sha256(path)>]/` (`tree/<files>` + `files.json` with every file's SHA-256; `PackageCache::for_skills` is the view with that prefix), verified on every load (a changed file is an error). `Lockfile.skills` (key → `LockedSkills { commit, tree }`, `tree` = hash of `files.json`; section absent without git skills); `resolve` and `resolve_skills` each rewrite only their own sections and keep the others. Nothing is built; the content is checked by whoever loads it (`SkillLibrary`). Tests `tests/git_skills.rs`.

**Shared lockfiles (ADR-0115):** `PackageResolver::resolve_in(spec, &Lockfile, lock_path)` and `resolve_skills_in` resolve against lockfile content instead of the file and return the lockfile as it should be, leaving writing to the caller (`resolve`/`resolve_skills` are these plus load and save); the host's agent tree gives each node its view of one lockfile.

**Setup (ADR-0118), module `setup`:** what the tool commands need around the resolver, moved down from the host so that `grauwolf-tools` needs no host: `lock_path(spec file)`, `POLICY_FILE`, `load_policy(file, &RegistryConfig)` (`GRAUWOLF_TOOL_POLICY`, else `grauwolf.toml` next to the spec or in the working directory), `registry_auth`, the resolver constructors `resolver`, `resolver_with`, `resolver_for`, `package_resolver`, `git_resolver`, `skills_resolver` (the isolated tool build is the `ModuleBuilder` of git packages; skills never build), `load_allowed_signers`, `generate_key` / `load_signing_key` / `load_public_key`, `pack_folder`, `load_packed`, `push_package`, `push_package_with`, `push_package_signed_with`. `grauwolf-host::packages` re-exports the module under the same paths.

**Tree lock (ADR-0115, ADR-0118), module `tree_lock`:** `lock_tree(&[LockNode { file, relative, spec }], &LockOptions { builder, locked, config, resolve_root })` resolves the tool packages and git skills of every node of an agent tree (first node = root) against the one `grauwolf.lock` next to the root: plain keys for the root, `<spec path relative to the root>#<key>` for every other node (`lock_key_prefix`, `lock_view`, `lock_merge`), stale entries dropped or, with `locked`, an error naming the entry; the lockfile is untouched when no node has packages or git skills. Returns a `LockedNode { package_tools, skills }` per node. `AgentTree::resolve` (grauwolf-agent-tree, used by the host) and `grauwolf-tools lock` both call it.

**Package metadata (ADR-0124), module `metadata`:** `package_annotations(&PackageManifest, &BuildInfo { created, rustc, checkout })` → the OCI annotations of a package (`org.opencontainers.image.title|version|description|licenses|authors|created|source|revision`, `vnd.grauwolf.tools.abi|built-with|rustc`; constants `*_ANNOTATION`, empty values left out; `source` from the manifest, else the remote of the git checkout; `revision` = the checkout's commit), `BuildInfo::created_from(SOURCE_DATE_EPOCH)`, `rfc3339(seconds)`, `GRAUWOLF_VERSION`. `PackedPackage::with_annotations(map)` puts them on the manifest (new digest); `setup::pack_folder` does that with `SOURCE_DATE_EPOCH` (else now; `pack_folder_built_at(dir, builder, seconds)` takes the date), `ToolBuilder::rustc_version()` and `grauwolf_git::checkout_of(dir)`. `Package.annotations` holds what a pulled manifest carries (empty for older packages, which still pull). `TestPackage::annotation`, `field` (top-level manifest field) and `limits(tool, json)` for tests.


`resolve` copies each tool's `limits` from the package manifest into `ResolvedTool.limits` (ADR-0124).


**Tool catalog (ADR-0124), module `catalog`:** `catalog_reference(value)` (a full `registry/repository[:tag]`, or a bare registry host = `<host>/grauwolf-catalog:latest`; digests refused), `CatalogStore::new(&client, reference)` with `read()` (→ `ReadIndex { index, digest }`, missing = empty index without digest; the artifact: image manifest with `artifactType` `application/vnd.grauwolf.catalog.v1+json`, empty config `application/vnd.oci.empty.v1+json`, one layer of that type with the index JSON), `update(&mut change, &present, &updated, key)` (read with digest → `change` (returns changed?; unchanged = nothing written) → write; the first write is a probe with an `If-Match` that cannot hold: `412` = the registry honours conditions (then `push_if` with `If-Match`/`If-None-Match` and a digest read-back), success = it ignores them (`Updated::ignores_conditions`, `ignores_conditions_note`): wait `with_settle` (default 300–1000 ms random), read again and ask `present(&index)` – our change is in, never a whole-index digest; a `412` or a missing change is retried from the start, at most `MAX_ATTEMPTS` = 5, then an error; with a key the index holding our change is signed by `push_signature`) and `signature(digest, keys)` → `IndexSignature::{Valid, Invalid, Unsigned, Unchecked}`. `catalog_entry(&client, ref, keys)` builds an entry from the manifest, config and annotations (modules not downloaded: sizes from the layer descriptors) plus the package's cosign signatures (stored in the entry; `fingerprints` = the given keys that verify one); `other_than_tool_package(client, ref)` (`None` = tool package, else the artifact type, config media type or own media type, e.g. of an image index); `entry_verdict(policy, entry)` = allowlist, and with `require_signatures` a stored signature that verifies with a policy key (read time only). Tests `tests/catalog.rs` (concurrent writers via `TestRegistry::interfere_with_next_put`, with and without conditional writes).

## Purpose
Fetches tool packages from OCI registries, verifies and caches them and resolves the `tool_packages` of a spec against the lockfile.

## Features / ADRs
E03 (F03.18, F03.20, F03.21 partly), ADR-0107, ADR-0108

## Allowed dependencies
- grauwolf crates: grauwolf-config (`RegistryConfig`, `Env`: the setup module), grauwolf-toolbuild (the module builder behind `setup`), grauwolf-git (fetching, tests: `test-git-server`), grauwolf-oci (registry client), grauwolf-spec (references, spec), grauwolf-tools (package format, `ResolvedTool`); dev: grauwolf-test (`TestDir` for temporary directories in tests)
- External: serde, serde_json, tokio, thiserror

Other dependencies only after checking against [ADR-0016](../../../docs/adr/0016-layered-architecture.md).

## Invariants
- Every manifest and blob is verified against its digest before it is used or cached; the cache is verified again on every load, a damaged entry is an error (no silent refetch).
- A cached or locked digest is never fetched again; a lock entry is fetched by digest, never by tag.
- Protocol, authentication and credential rules (plain http only for localhost, secrets never in errors, lazy credential lookup) are invariants of grauwolf-oci; this crate adds no HTTP code of its own.
- The package format itself (`PackageManifest`) lives in grauwolf-tools, the reference syntax in grauwolf-spec. Signatures: see the stage 4 notes. This crate never builds anything itself (`ModuleBuilder`) and has no git code of its own.
- Prebuilt `.wasm` files in a git folder are ignored: modules are always built from the sources.
