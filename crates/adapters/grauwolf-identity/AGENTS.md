# grauwolf-identity

**Layer:** `adapters` · **Status:** ADR-0111 stages 1 and 3. The Txn-Token (`TxnClaims { iss, aud, sub, name?, upn?, txn, purp?, azd?, req_wl, iat, exp, chain_exp }`; `issue(signer, claims)` signs ES256 with JOSE `typ` `txntoken+jwt` and the signer's `kid`; `check(token, key, audience, issuer?, now)` verifies signature, `typ`, `aud`, `iss`, `exp` with `LEEWAY_SECS`; `DEFAULT_LIFETIME` 15 min, `MAX_CHAIN_LIFETIME` 8 h, `chain_exp` is a grauwolf claim that caps renewals). Ports: `TokenSigner` (`key_id`, `sign(kid, input)` → raw `r || s`, `public_keys`) with `MemorySigner` (key in memory) and `TransitSigner` (OpenBao Transit through `grauwolf-openbao`: `kid` = `<key>-v<version>`, the latest version signs, every readable version is published; key versions cached for `TRANSIT_KEYS_TTL`; tokens from a `TokenSource`); `PersonTokenVerifier` with `EntraVerifier` (`EntraSettings { tenant, issuer, audiences (any of them is accepted), scope, jwks_url? }`: RS256 from the tenant's JWKS – explicit URL or OpenID discovery of the issuer –, `tid`, `iss`, `aud` (text or list), `exp`/`nbf`, `scp` contains the scope; `Person { oid, name, upn (else preferred_username), tid }`). `KeyCache` (internal) loads a JWKS on first use and again for an unknown `kid`, such refreshes at most once per `MISS_COOLDOWN`. `IdentityPolicy` (`{ "callers": { "<spiffe id>" | "<prefix>/*": { "purposes"?: [..] } }, "grants": { "agents": { "<id or prefix/*>": { "purposes"?: [..] } }, "triggers": ["<id or prefix/*>"] } }`, both sections optional, exact wins over the longest prefix; `allows(caller, purpose)` checks `callers`, `allows_grant(agent, trigger, purposes)` the `grants` section (every purpose of the grant must be allowed); `watch(path, POLICY_RELOAD_INTERVAL)` re-reads a changed file, keeps the old one on errors). `IdentityService` (no HTTP): `token(caller, TokenRequest { subject_token, subject_token_type?, purpose? })` – entry (policy, then the person's token; `req_wl` = caller, new 128-bit `txn`) or renewal (own keys, `aud`, `iss`, `exp`; any caller of the token's trust domain; `txn`, person, `purp`, `req_wl`, `chain_exp` kept; `exp` never beyond `chain_exp`); the kind is the given type or, without one, `iss` = own issuer means renewal; `jwks()`, `config()` (`issuer`, `trust_domain`, `person_issuer`). `IdentityError::{BadRequest, Unauthorized, Forbidden, NotFound, Unavailable}` with `status()` 400/401/403/404/503 (the client maps a `403` of the service to `Forbidden`, any other refusal to `Unauthorized`); no token in any message. Agent side: `IdentityClient::new(url, own trust domain, Option<Arc<ClientAuth>>)` (mTLS and/or JWT-SVID bearer to the service), `config()` (fetched once), `is_person_token(token)` (a `sub` of `spiffe://…` is a JWT-SVID without asking; else `iss` = the service's `person_issuer`), `exchange(access token)`, `grant(grant id, trigger)` (a grant run, stage 3), `renew(txn token)`, `verify(txn token)` (`TxnTokenVerifier`: the service's `jwks.json`, `aud` = own trust domain, `exp`); `TxnToken` (token + verified claims, `Debug` without the token); `RunDelegation` implements `grauwolf_tools::Delegation` and renews within `RENEW_BEFORE` (60 s) of `exp`. People on the command line (`grauwolf login`): `DeviceLogin::new(DeviceEndpoints::entra(authority, tenant), client_id, scope)` – `start()` (RFC 8628 device authorization: `user_code`, `verification_uri`, `interval`, `expires_in`; the device code is private and not in `Debug`), `wait(&code)` (polls the token endpoint: `authorization_pending` waits, `slow_down` adds `SLOW_DOWN_STEP` – `with_slow_down_step` for tests –, `expired_token`, `access_denied` and the local deadline end it), `refresh(refresh token)` (keeps the old refresh token when the server does not rotate it); `OAuthTokens` without tokens in `Debug`. Feature `testing`: `testing::FakeEntra` (RSA keys made at test time, `token(oid, name)`, `claims`, `sign`, `jwks`, `rotate`, `settings(jwks_url)`), `testing::TrustingPeople`.

Grants (stage 3): `Grant { id (grt_ + 128 bit hex), owner: GrantOwner { oid, name?, upn? }, agent, trigger (SPIFFE IDs), purposes, valid_until, max_run (s), created, last_used? }`; `Grant::new(owner, GrantRequest { agent, trigger, purposes, valid_until?, max_run? }, now, max_run_limit)` checks the IDs, `valid_until` (default `DEFAULT_GRANT_VALIDITY` 30 days, at most `MAX_GRANT_VALIDITY` 90 days) and `max_run` (default `DEFAULT_MAX_RUN` 4 h, 60 s up to the limit); `is_grant_id` (only well-formed IDs reach a store path). Port `GrantStore` (`save`, `save_token`, `get`, `token`, `list`, `delete`) with `MemoryGrantStore` and `OpenBaoGrantStore` (KV v2: metadata at `<mount>/identity/grants/<id>` (`GRANTS_PATH`), the refresh token apart at `<mount>/identity/grant-tokens/<id>` (`GRANT_TOKENS_PATH`, field `refresh_token`); store errors are `Unavailable`). `testing::FakeKv` is a KV v2 `Transport` in memory (`data`, `paths`, `set_down`). Port `RefreshRedeemer` (`redeem(refresh token)` → `Redeemed { access_token, refresh_token }` (the rotated one, else the old), refused `Unauthorized`, unreachable `Unavailable`) with `PublicClientRefresh::new(TokenEndpoint::{Url, Discovery(issuer)}, client_id, scope)`. `IdentityService::with_grants(store, redeemer)` (without it every grant call is `Unavailable`): `create_grant(access token, CreateGrant { grant: GrantRequest, refresh_token })` (person verified, `Grant::new` with `max_chain_lifetime` as the limit, `allows_grant` else `Forbidden`, the refresh token redeemed once – refused `BadRequest` – and its person must be the same `oid` else `Forbidden`; the rotated token is stored), `own_grants(access token)`, `revoke_grant(access token, id)` (another person's grant is `NotFound`). Grant runs at `token`: `subject_token` = the grant ID with `subject_token_type` `GRANT_TYPE` (or no type and a `grt_` prefix) and `trigger` = the caller of the entry agent; checks in order: grant exists (`401`), caller = its agent and trigger = its trigger (`403`), `allows_grant` (`403`), valid (`401`), the stored refresh token redeemed (`401`/`503`) and naming the owner; the rotated token and `last_used` are stored; claims: `purp` = the purposes joined by spaces, `azd` = `{ "grant": id }`, `chain_exp` = now + `max_run`; one audit line (`grant <id> used: oid trigger agent txn`). People and triggers (`people.rs`): `GrantsClient::new(identity url)` – `create(access token, &GrantRequest, refresh token)`, `list(access token)`, `revoke(access token, id)` (the service's 400/401/403/404 become the matching `IdentityError`, anything else `Unavailable`); `call_agent(url, &CallerCredential::{Workload(ClientAuth), Bearer, None}, grant?, input, timeout)` posts `{input}` with mTLS/JWT-SVID or a bearer and `Grauwolf-Grant`, returns `CallAnswer { status, body }` (`grauwolf call`). `testing::FakeEntra` also has `refresh_token(oid, name)`, `disable(oid)`, `is_valid_refresh_token`, `redeemer()` (rotates on every redemption, refuses a disabled person with `invalid_grant`).

## Purpose
Delegation (ADR-0111): everything about Txn-Tokens and people's tokens that the identity service (`grauwolf identity serve`) and the agents (`grauwolf-server`) share, with Entra and the key store behind ports.

Used by: `grauwolf-host` (`identity::agent_client`, `identity::service`; it re-exports `DeviceLogin` for `grauwolf login` of `grauwolf-cli`), `grauwolf-server` (the identity service's routes; in every agent the entry exchange, the hop verification and `RunDelegation` around every run, `tests/delegation.rs`).

## Features / ADRs
ADR-0111, ADR-0109, ADR-0110

## Allowed dependencies
- grauwolf crates: grauwolf-openbao (Transit), grauwolf-spiffe (`SpiffeId`, `ClientAuth`), grauwolf-tools (the `Delegation` port); dev: grauwolf-spiffe with `testing`, grauwolf-test
- External: aws-lc-rs (ES256 and RS256; already in the tree through rustls), base64, futures-util, reqwest, serde, serde_json, thiserror, tokio (sync, time, rt); dev: tokio (macros), wiremock

## Invariants
- A token never appears in an error, in `Debug` output or in a log line; errors name the reason only.
- Only `ES256` Txn-Tokens and `RS256` access tokens verify; `none` and any other algorithm never do.
- Unverified claims (`peek_claims`) only choose a code path, never grant anything.
