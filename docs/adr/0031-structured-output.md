# ADR-0031: Structured LLM responses (`llm_request_structured`)

- **Status:** Accepted (implementation of slice 2, 2026-11-06); refines ADR-0022
- **Date:** 2026-11-06

## Context
Named types (ADR-0022) are only useful once a node produces them. An LLM should return a response that matches a type from `types` (F01.10, F01.11, F05.9 `nodeLLMRequestStructured`). The interpreter and the generated crate must react the same way (ADR-0015), even though only the generated crate has real Rust types.

## Decision
- **Node kind** `llm_request_structured` with `params: { "type": "<name from types>" }`, signature `string → <type>`. Spec validation reports missing parameters and unknown types.
- **Port:** `LlmClient::execute_structured(prompt, model, &StructuredOutput { name, schema })`. The default implementation is the *manual* strategy: it appends a system instruction with the JSON schema and calls `execute` without tools. Provider adapters (slice 3) override it with native support (*native* strategy).
- **Same schema in both modes:** always the schema from the spec, not one generated by schemars. Generated structs implement `grauwolf_agents::Structured` for this (name and schema from the spec).
- **Normalization instead of just checking:** `grauwolf_agents::structured::normalize(schema, value)` checks a JSON value against the schema subset supported by the generator and brings it into the form that a serde round trip through the generated struct would produce (unknown fields and `null` in optional fields are dropped, `number` becomes a floating-point number). The interpreter thus normalizes the LLM response; the generated crate deserializes into the struct. This way both modes produce the same output and reject the same responses.
- The response may be inside a Markdown code block; the node removes the fences before parsing.
- **Fix retry (F01.11):** Optional parameter `retries` (default 0). If a response is unusable, the node reports the error as a user message and asks again; all attempts stay in the history. In generated code as `llm_request_structured_with_retries::<T, N>`.

## Consequences
- Structured responses work with every `LlmClient`, even without native provider support.
- The schema subset (object, string, integer, number, boolean, array) is defined in two places: the generator (Rust types) and `normalize` (values); the equivalence test keeps them together.

## Addendum (2026-11-09): schema subset actually supported
- The generator (`crates/domain/grauwolf-generator/src/types.rs`) allows `object` only at the top level of a type; fields may be `string`, `integer`, `number`, `boolean`, and `array` (with `items` of these types). It rejects nested objects with `UnsupportedType`; `normalize` (`grauwolf-agents/src/structured.rs`), on the other hand, handles them recursively. The narrower subset of the generator is binding for specs that are meant to run in both modes.
- `enum` is checked neither by the generator nor by `normalize`; for a string field with `enum`, grauwolf accepts any text (whether a provider enforces it in native strategy depends on the provider).
- The native strategies (slice 3) are implemented: Anthropic, OpenAI and Ollama override `execute_structured`.
