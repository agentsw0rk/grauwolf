# ADR-0038: RAG – embedder port, vector store, search as a tool

- **Status:** Accepted (User, 2026-11-06)
- **Date:** 2026-11-06

## Context
Agents should answer questions about their own documents (E08). This requires embedders, vector storage, and retrieval, and the search should be available as a tool (F08.8).

## Decision
- New domain crate `grauwolf-rag`: `Embedding` with cosine similarity (F08.1), port `Embedder` (F08.2), `Document`/`Chunk` with simple splitting into sections, port `VectorStore` with `InMemoryVectorStore` (F08.5, F08.6), `Retriever` (indexing and retrieving the best k sections).
- The search is offered as a tool (`search_tool`): the LLM itself decides when to look something up; graphs need no new node kind for this.
- Provider adapters implement `Embedder` (first Ollama `/api/embed`, OpenAI follows).
- In specs, a section `knowledge` describes document sources (files/directories), the embedding model, and the name of the search tool. The CLI indexes at startup and registers the tool; the index lives in memory for now.

## Consequences
- RAG uses the existing tool loop; every model with tool support can use it.
- Indexing at startup costs time for large collections; a persistent file or external vector store (F08.6, F08.7) follows as needed.

## Addendum (2026-11-09): follow-up steps implemented
- `Embedder` is implemented for Ollama and OpenAI.
- The index can be kept persistently in a file with `knowledge.index`; at startup only new or changed files are embedded (ADR-0057). Searching continues in memory (`InMemoryVectorStore`).
- Provisioning no longer lives in the CLI but in the facade (`grauwolf::external::tools`, ADR-0050).
